## 1. 设计基准：Obsidian 原生设计语言

- **外观原则**：ReelLudic 是 Obsidian 插件，UI 必须像 Obsidian 原生的一部分——克制、功能性、无网页感。
- **参考基准**：Obsidian 内建界面（设置页、模态框、菜单、悬停提示）+ 官方主题变量体系。
- **禁用的网页风**：流光/辉光/呼吸动画、渐变填充、3D 倾斜、emoji 图标（业务图标用 Lucide `setIcon`）、圆角夸张、阴影堆叠（与项目「朴素功能向」约定一致）。

## 2. CSS 全局变量体系（跟随主题，禁止硬编码色值）

| 用途 | 首选变量（Obsidian 内建） |
|---|---|
| 背景/面板 | `--background-primary` `--background-secondary` `--background-modifier-hover` |
| 边框 | `--background-modifier-border` |
| 文字 | `--text-normal` `--text-muted` `--text-faint` |
| 强调 | `--interactive-accent` `--text-on-accent` |
| 字体 | `--font-text` `--font-ui-small` `--font-ui-medium` `--font-monospace` |

- **规则**：自定义样式一律引用上述变量；确实需要独立色值时（如高亮/类型色）抽成 `rl-*` 变量或语义类，并注释用途。
- 类型识别色（电影蓝/书籍绿等）集中在 `data/types.ts TYPE_COLORS`，CSS 侧通过语义类引用，不散落硬编码。

### 2.1 语义色板 `--rl-*`（2026-09-11 批C 建立，强制）

**为什么不直接用 Obsidian 的 `--color-yellow` 一类**：那套色主要为图形/边框设计，直接拿来当**正文文字色**时未必够。本插件此前把一批色值直写进组件，实测浅色主题下最低只有 **2.44:1**（WCAG AA 正文要求 4.5:1），反向也有 `#c0493f` 在暗底只有 3.39:1。故自建一层语义色板。

**结构原则（重要）**：`styles.css` 文件头的 `:root` 放**原色**，`.theme-light` / `.theme-dark` **各自只列「自己这侧不达标」的项**。因为这套原色本就是照深色主题调出来的 —— 暗底大多天然达标，所以深色主题几乎原封不动（观感不变），只有浅色主题需要补正。覆盖值一律取「保持原色相、只移动亮度」的**最小必要幅度**，不要顺手换成另一套色。

| 变量 | 用途 | 说明 |
|---|---|---|
| `--rl-score` | 评分 / 点亮星 | **⚠️ 浅色深色共用同一色值**（用户 2026-09-11 指定），见下方注意事项 |
| `--rl-score-mid` | 星级 1–3 灰 | 同上，共用 |
| `--rl-score-none` | 未评分 | 同上，共用 |
| `--rl-score-input` | 评分输入框未点亮星 | 同上，共用 |
| `--rl-danger` / `--rl-danger-strong` | 危险 / 警告文字、右键危险项 | 浅底达标；暗底在 `.theme-dark` 提亮 |
| `--rl-good` | 正向状态文字 | 暗底达标；浅底在 `.theme-light` 压深 |
| `--rl-warn` | 次级提醒文字 | 暗底达标；浅底在 `.theme-light` 压深 |
| `--rl-good-bar` / `--rl-good-soft` / `--rl-danger-soft` | 进度条填充三档 | 图形，门槛 3:1；两主题均达标 → 不需覆盖 |
| `--rl-badge-*` | 状态徽标四色（**白字** on 底色） | 9px 粗体白字，按正文 4.5 计；两侧都需覆盖 |

**⚠️ 评分与星级为什么两主题共用（以及代价）**：用户明确要求这两个主题下**同色**，以便观感统一。代价是**单色在数学上不可能两主题同时达 AA** —— 白底需要相对亮度 ≤0.183，暗底需要 ≥0.230，两个区间不相交；单色的理论最优也只有两主题各 **4.11:1**（仍未达 4.5）。故这四色沿用原色，浅色主题下对比度不足属**既知取舍**，已记入根 README「已知问题与限制」。**若将来要恢复浅色可达性，必须先找用户确认放弃「共用」**。

- 每个变量的实算对比度（浅底对 `#ffffff`、暗底对 `#1e1e1e`）都写在 `styles.css` 文件头的行内注释里。**改色值必须重算并同步注释**，不要凭肉眼判断。门槛：正文 4.5:1、大号文本与图形 3:1（9px 粗体算正文）。
- 复核方式：用任意符合 **WCAG 2.1** 的对比度计算器（或几行相对亮度公式：`L = 0.2126R + 0.7152G + 0.0722B`，取 `(Lmax+0.05)/(Lmin+0.05)`）逐项算一遍。批C 用的脚本（找不达标项 / 搜候选色 / 从 `styles.css` 解析变量做终检）在 AI 工具工作区，未纳入本仓库。

## 3. 组件库约定（rl-* 前缀 + 语义命名）

- **类名体系**：`rl-` 前缀 + 语义名（如 `rl-reader-toc-tab`、`rl-watch-btn`）；组件级样式写入 `styles.css` 对应分区注释（`/* ── xxx ── */`）。
- **优先复用 Obsidian 内建**：按钮 `mod-cta`、危险操作 `rl-nc-danger`（项目已有）、通用确认弹窗 `ConfirmModal`。
- **文件关联一律系统对话框**：所有类型（影视/书籍/游戏/音乐）的「浏览…」直接唤起系统文件管理器（`main.pickSystemFile`，会话内记忆上次目录）。**不再提供「从库中选择 / 从系统浏览」二次弹窗**（原 `PickFileSourceModal` 已删除，2026-09-10）——多一步点击无收益，vault 内文件在系统对话框里同样可选。路径格式（vault 相对 / 系统绝对）由 `toRel` 参数在选后自动归一，与弹窗选择无关。
- **浮出菜单（右键菜单/浮层）边界自适应强制走 `pure/menuPlacement.placeMenu`**：视口系算落点（贴鼠标 → 越界翻转 → 仍越界钳制 → 超高/超宽封顶 + 内部滚动）。⚠️ 禁止把「锚点相对坐标」直接与视口宽高比较（锚点越靠内容末尾越失准，边缘触发时菜单会跑出屏幕）。
- **新增组件先查 styles.css 是否已有可复用类**（rl-btn / rl-input / rl-ep-row 等），禁止重复定义相似样式。
- **交互规范**：
  - **Hover 提示统一标准（v3，2026-09-09 修订，强制）**：鼠标悬停说明一律用 **`data-tip` 属性 + 全局自绘气泡**（深色 tooltip 风，**固定在元素正下方**、下方空间不足翻上方、视口内钳制，实现见 `src/services/globalTooltip.ts` + `styles.css .rl-tip`，plugin onload 已全局委托，元素**无需自行绑定**）。**禁止使用 `title` 原生黄条**。⚠️ **`aria-label` 并存禁令（v3 新增）**：Obsidian 会对悬停目标（含祖先就近匹配）带 `aria-label` 的元素自动弹官方气泡——因此 `aria-label` 与 `data-tip` **不得放在同一元素或其祖先链上**（会叠出两个气泡，官方气泡后出覆盖自绘气泡）。读屏命名与视觉提示分流规则：元素有可见文字 → 直接删 `aria-label` 只留 `data-tip`；纯图标按钮 → 不挂 `aria-label`，读屏名用可见/隐藏文本或 `aria-labelledby`（指向文本元素；**不触发官方气泡**）；容器无障碍命名（如 `role="dialog"`）→ 一律 `aria-labelledby` 指向其可见标题。新增/修改任何 hover 提示都必须写 `data-tip`（Svelte：`data-tip="…"` / `data-tip={expr}`；DOM：`attr: { 'data-tip': x }` 或 `el.setAttribute('data-tip', x)`），文案支持多行（`\n`）。已踩坑：2026-09-09 EntryForm 4 浮层 + 观看/检索按钮双提示（v3 修复）。
  - hover 浮现按钮：focus 后需 `blur()` 防悬停层残留（AGENTS 坑点）。
  - 按钮点击后失焦：`ev.currentTarget.blur()`。
- **Svelte 组件**：事件用 `on:click`（Svelte 4 红线）；模板不写 `as`/`!` 断言、数组下标 `bind:value`（AGENTS 坑点）。

## 4. 设计流程：多方案对比 + 排雷法（AI 必做）

新增 UI/交互前，向用户输出：

1. **多方案对比表**：≥2 个候选方案，列「做法 / 优点 / 风险与坑」（如音乐库方向 A/B/C 对比）。
2. **排雷**：明确每个方案的技术坑（库限制、Obsidian 行为差异、数据兼容），推荐方案须先排除 P0/P1 风险。
3. **象形示意**：UI 增删改给前后对比 ASCII 图，经用户确认后实现（UI 审批规则）。

## 5. 评审清单（改动完成后自查）

- [ ] 全部颜色走 CSS 变量，无硬编码色值（除语义色/高亮）；文字色一律用 §2.1 的 `--rl-*` 语义色板，改色值须重跑 `verify-palette.cjs`
- [ ] 复用已有 rl-* 类与 Obsidian 内建组件，无重复定义
- [ ] 无网页风动画/装饰
- [ ] Hover 提示一律 `data-tip`（自绘气泡），无 `title` 黄条残留；**`aria-label` 不与 `data-tip` 同元素/祖先链并存**（会双提示）；容器/图标读屏命名用可见文字或 `aria-labelledby`
- [ ] **键盘可达**：可点击容器（卡片 / 列表行 / 自定义可点 div）必须有 `role` + `tabindex="0"` + `on:keydown`（Enter）+ **`:focus-visible` 可见聚焦环**——没有聚焦环的键盘可达等于不可用
- [ ] **表格行不要用 `role="link"`**：那会顶掉 `<tr>` 的 `row` 含义、毁掉表格语义。正确做法是把可聚焦元素放进标题单元格（`<span role="link" tabindex="0">`）
- [ ] Svelte 事件 `on:` 指令、无 `as`/`!` 模板断言
- [ ] 新类样式入 styles.css 对应分区，构建后产物验证

## 6. 主题 B（现代）豁免清单（2026-09-12 用户确认）

§1 禁用「阴影堆叠、渐变填充、圆角夸张、网页风动画」。`rl-theme-modern` 作用域内的以下偏离**经用户确认豁免**：

| 被豁免的规则 | 主题 B 的具体表现 | 豁免理由 |
|---|---|---|
| 禁止阴影堆叠 | 卡片双层投影、弹窗双层投影 | 现代风靠阴影建立层级，是该风格的**定义性特征**而非装饰 |
| 禁止圆角夸张 | 圆角 6→16px、控件全圆 99px | 同上 |
| 禁止网页风动画 | 页签指示器滑动（.28s 弹性缓动） | 滑动指示器是分段控件的**标准交互**，非炫技 |
| 禁发光 | 主按钮辉光（`--rl-t-shadow-cta`） | 用于强调唯一主操作，非装饰性发光 |

**豁免边界（防止无限扩张）**：

- 豁免**仅适用于 `.rl-theme-modern` 作用域内**；`native` 主题与任何全局样式**仍适用原规范**。
- 豁免**不含**：渐变填充、3D 倾斜、emoji 图标、呼吸动画、`!important`。
- 主题 B 的**文字对比度仍须满足 §2.1 的 AA 门槛**（形态可豁免，可读性不可）。
- 新增豁免项须经用户确认后写入本节。

**实施要点**：`rl-theme-modern` 挂在 `document.body`（单点挂载覆盖主界面与全部弹窗）。
主题差异一律走 `--rl-t-*` 令牌（`styles.css` 定义，`:root` 原值 + `.rl-theme-modern` 覆盖）；
**唯一允许的组件内结构分支**是页签（需增删 DOM 节点，见 `HomeView.svelte`）。

### 6.1 令牌层 `--rl-t-*` 使用纪律（强制）

`--rl-t-*` 管**形态**（圆角 / 阴影 / 位移 / 时长 / 缓动），与管**颜色**的 `--rl-*` 正交。
`styles.css` 内 `:root` 给原生原值，`.rl-theme-modern` 只列差异项。

- **顺序敏感**：`.rl-theme-modern` 必须写在令牌 `:root` **之后**，否则 modern 覆盖静默失效。
- **fallback 必须给原值**：一律写 `var(--rl-t-radius-lg, 8px)`。第二参数缺失时，令牌一旦
  解析不到该属性会变成**空白**（静默破样式），这是本机制最危险的失败模式。
- **只迁移「能精确匹配某一档位」的原值**（2026-09-12 用户裁定）：
  `3px→sm` / `6px→md` / `8px→lg` / `999px→pill`。
  无档位的值（`2/4/5/7/9/10/12px`）**保持硬编码** —— 「吸附到最近档位」会改变 native 观感，
  违反「native 与 1.0.2 逐像素一致」的验收标准。
- **诊断法**：某处主题 B 不生效 ⇒ 该处值仍是硬编码（没走令牌）。
- **同特异性规则的顺序**：同类选择器（如 `.rl-theme-modern .modal` 与
  `.rl-theme-modern .modal.rl-reader-immersive`）冲突时靠**书写顺序**决胜，
  覆盖用的规则必须写在被覆盖者**之后**。
- **禁止加 `!important`**（见豁免边界）；需要更高优先级时提高选择器特异性。
- 结构型差异（增删 DOM 节点）**不能**只靠变量表达 → 必须走 `{#if}` 结构分支。
