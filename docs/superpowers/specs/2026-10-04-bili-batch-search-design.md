## 1. 目标与非目标

**目标**：影视（tv/anime）条目里，一条命令把**所有未关联的集**按「作品标题 + 第N集」在 B 站各搜一次，
把结果整理成**一张确认表**（每行一集、带候选与分P 标记），用户确认后一次性填入集链接数组。

**非目标**（明确不做）：
- ⛔ 不自动落库 —— 与既有全部关联入口同一条纪律：只写内存副本，仍要点「保存」。
- ⛔ 不碰**已关联**的集（沿用 #518 用户裁定「不得跨集覆盖」）。
- ⛔ 不并发、不自动重试轰炸（B站 风控 412 是实测事实）。
- ⛔ 不做「翻页取更多候选」（搜索接口固定 20 条/页，本仓只取第 1 页，既有口径）。
- ⛔ 不对**每个**候选都取分P 数（请求量爆炸）—— 只标「当前选中的那条」，其余按需展开时再取。

## 3. 数据流

```
点击批量按钮
  → unfilledEpIndexes(episodeUrls, total)        // 纯：未填集下标（升序）
  → 逐集串行：
        query = biliEpisodeQuery(作品标题, 集号, 集标题)   // 与单集搜索同一份真源
        dlBiliSearch(query)  → videos（前 20 条，原样）
        dlBiliView(videos[0].bvid) → parts.length          // 只给「当前选中（= 第一条）」标分P 数
        sleep(BATCH_GAP_MS)                                // 限速
  → 每集产出一行 BatchRow（写进组件状态）
  → 渲染确认表（进度 / 停止 / 继续 + 每行候选 + 分P 胶囊 + 勾选 + 换一条）
  → 用户确认 → batchCheckedRows(rows) → 写 episodeUrls[epIndex]（内存副本）
```

## 4. 纯逻辑（`src/pure/biliBatch.ts`，可单测）

| 导出 | 作用 |
|---|---|
| `BATCH_GAP_MS` | 请求间隔（600ms）—— 两入口共用的**唯一**限速常量 |
| `unfilledEpIndexes(urls, total)` | 未填集下标（`urls[i]` 空 且 `i < total`），升序 |
| `makeBatchRows(targets)` | `{epIndex, epNo, query}` → `BatchRow[]`（候选、已取分P 数、选中下标、勾选、错误） |
| `partCountLabel(n)` | 分P 胶囊文案：`1P` / `52P` / 空串（未知） |
| `pickedCandidate(row)` | 当前选中的候选（无 ⇒ `undefined`） |
| `pickedUrl(row)` | 要填入的链接（= 选中候选的 `webUrl`，即 P1） |
| `batchCheckedRows(rows)` | 勾中且有候选的行（点「填入」时真正要写的那批） |
| `batchProgressText(done, total, epNo)` | 跑的时候那句进度：`正在搜索 12/52 · 第 12 集…` |
| `batchStopText(doneEpNo, reason)` | 停下那句：`已搜到第 12 集就停下了（原因）…` |
| `canFillBatch(rows)` | 至少要有一行勾中且有选中候选（保存按钮禁用判据） |

## 5. 请求策略（风控是硬约束）

- **串行**：一集处理完才动下一集（⛔ 不 `Promise.all`）。
- **每集 2 个请求**：`search`（1）+ `view`（1，只为标第一条的分P 数）。
  ⚠️ `dlBiliSearch` / `dlBiliView` **失败会各自重取 `buvid3` 再试一次** ⇒ 最坏一集 6 个请求。
- **间隔 `BATCH_GAP_MS = 600ms`**（两集之间）。
- **遇错即停**：`error` 非空（含 412 风控）⇒ 立刻结束本轮，已搜到的照常进表，
  表头写 `batchStopText(...)`，给一颗**「继续」**按钮（从下一集接着跑）。
- **可随时停止**：跑动中显示「停止」，点了把 `running` 置假，本轮结束（已搜到的保留）。
- **不设集数上限**（用户接受 600ms / 2 请求的代价）；实际约束由「停止 + 继续」提供。

## 6. 确认表 UI

每行（`.rl-bili-batch-row`）：

| 段 | 内容 |
|---|---|
| 集号 | `第 12 集`（`.rl-bili-batch-ep`） |
| 候选 | 选中那条：封面缩略（`referrerpolicy="no-referrer"`）、标题、UP 主、时长、**分P 胶囊**（`52P` / `1P`） |
| 链接 | 选中候选的 `webUrl`（`.rl-bili-batch-url`，省略号截断 + `data-tip` 全串） |
| 勾选 | 默认勾「有候选」的行；无候选/出错的行禁用并显示原因 |
| 换一条 | 展开该集的其余候选（点某条即替换选中；**展开时才对那几条取分P 数**） |

表头：`共 N 集待搜 · 已选 M 集`；跑动中换成进度句 + 「停止」。
表底：`填入勾中的 M 集`（⛔ 只写内存副本，仍要点「保存」）。

## 7. 错误处理

| 情形 | 表现 |
|---|---|
| 某集搜索**无结果** | 该行标「未搜到」，不勾、不进填入 |
| 某集搜索**失败**（412 / HTTP / 解析） | 该行标原因；**整轮在此停下**（后面的集标「未搜」），可「继续」 |
| `view` 失败 | 分P 胶囊留空（`—`），链接照常可用（⛔ 不因为标不出分P 就丢掉这条） |
| 全部未填集为空 | 按钮点了直接一句 notice「本条目没有未填的集」，不开卡 |
