## 1. 目标与非目标

### 目标

1. 提供**两套可切换的视觉主题**，让用户按偏好选择观感：
   - **主题 A「原生」**：现有观感，Obsidian 克制功能风（**默认**，保证老用户无感升级）
   - **主题 B「现代」**：参考图二的 App 风（分段控件、大圆角、浮起卡片）
2. 在设置页「外观」区提供切换入口。
3. 借这次机会**收口历史遗留问题**：清理已死的 `colorTheme` 机制。
4. 把主题能力做成**可扩展结构**：将来加第三套主题只需加一组变量。

### 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 不纳入阅读器（TXT/EPUB/PDF）与播放器 | 这些界面本身已高度定制（沉浸式 / 全屏），纳入会大幅推高回归风险，且用户在澄清阶段已明确排除 |
| 不做主题跟随 Obsidian 明暗自动反转 | 两套主题与「明暗」是**正交**的两个维度，主题不改变明暗行为（见 §3.1） |
| 不做用户自定义配色 | 超出本次范围，YAGNI |
| 不改任何数据模型 / 存储格式 | 本版本纯 UI 层 |

## 2. 关键约束：Svelte scoped 样式特异性（架构决策依据）

这是本设计最重要的一条技术前提，实测自编译产物 `main.js`：

```
.rl-tabs.svelte-pvefsy button.on.svelte-pvefsy.svelte-pvefsy     /* 特异性 (0,5,0) */
.rl-tabs.svelte-pvefsy button.svelte-pvefsy.svelte-pvefsy        /* 特异性 (0,4,0) */
```

**含义**：组件内 `<style>` 经 Svelte 编译后会附带 scoped 哈希类，把特异性推到 `(0,4,0)`–`(0,5,0)`。
而在 `styles.css` 里写自然的主题覆盖，例如：

```css
.rl-theme-modern .rl-tabs button.on { ... }   /* 仅 (0,3,0) */
```

**必然被组件内样式压掉**。若硬拼特异性，将陷入 `!important` 或堆叠哈希类的泥潭；且覆盖效果**依赖 scoped 哈希数量**，将来升级 Svelte 版本可能静默失效。

→ 因此本设计采用 **「CSS 变量重定向为主 + 组件内结构分支为辅」**。

## 3. 设计

### 3.1 两个正交维度（重要概念澄清）

必须区分这两个维度，它们**互不干扰**：

| 维度 | 取值 | 由谁控制 | 影响 |
|---|---|---|---|
| **明暗** | 浅色 / 深色 | Obsidian 本体（`body.theme-light` / `.theme-dark`） | 背景、文字、边框的明暗 |
| **主题** | 原生 / 现代 | ReelLudic 设置项 | 圆角、间距、阴影、控件结构 |

**结论**：两套主题**都必须在浅色与深色下成立**。`--rl-*` 变量体系沿用既有的「`:root` 放原色 + 各主题块只补差项」结构，在此基础上**新增一维主题类**。

### 3.2 变量分层

新增一层**主题变量**（`--rl-t-*`，t = theme token），与既有的**语义色板**（`--rl-*`）分工：

```
:root              → --rl-t-* 默认值 = 主题 A（原生）的取值
:root              → --rl-* 语义色（既有，保持不变）
.theme-light/.dark → --rl-* 仅补明暗不达标的项（既有，保持不变）

.rl-theme-native   → （全部沿用 :root 默认，无需声明）
.rl-theme-modern   → 只覆盖需要变的 --rl-t-* 项
```

**主题变量清单**（主题 B 的取值即演示页已验证值）：

| 变量 | 用途 | 主题 A | 主题 B |
|---|---|---|---|
| `--rl-t-radius-sm` | 小控件圆角（按钮/输入框/chip） | `6px` | `99px`（胶囊） |
| `--rl-t-radius-md` | 中容器圆角（卡片/面板） | `6px` | `16px` |
| `--rl-t-radius-lg` | 大容器圆角（弹窗） | `8px` | `16px` |
| `--rl-t-border` | 容器边框 | `1px solid var(--background-modifier-border)` | `none` |
| `--rl-t-shadow-card` | 卡片静态阴影 | `none` | `0 1px 3px rgba(0,0,0,.10), 0 4px 12px rgba(0,0,0,.06)` |
| `--rl-t-shadow-hover` | 卡片悬停阴影 | `none` | `0 10px 30px rgba(0,0,0,.22)` |
| `--rl-t-shadow-modal` | 弹窗阴影 | `none` | `0 2px 8px rgba(0,0,0,.09), 0 16px 44px rgba(0,0,0,.15)` |
| `--rl-t-lift` | 悬停上移量 | `2px` | `7px` |
| `--rl-t-scale` | 悬停缩放 | `1` | `1.025` |
| `--rl-t-focus-ring` | 输入框聚焦光环 | `none` | `0 0 0 3px color-mix(in srgb, var(--interactive-accent) 20%, transparent)` |
| `--rl-t-dur` | 过渡时长 | `.18s` | `.3s` |
| `--rl-t-ease` | 过渡曲线 | `ease` | `cubic-bezier(.34,1.3,.64,1)` |

> **为什么分 sm/md/lg 三档而非一个 `--rl-t-radius`**：现状圆角确实分三档使用（6/8px 用于不同层级），单一变量会丢失层级感。

### 3.3 主题类挂载

**⚠️ 本节方案在计划阶段已被替换**（原文的 `RlModal` 基类方案废弃，保留记录见文末「方案修订」）。

采用**单点挂载**：主题类挂在 `document.body`，由 `main.ts` 的 `applyUiTheme()` 统一维护。

| 挂载点 | 位置 | 方式 |
|---|---|---|
| 主界面 **与全部弹窗** | `document.body` | `document.body.toggleClass('rl-theme-modern', isModern)` |

**为什么单点挂载优于逐 Modal 基类**：Obsidian 的所有 Modal 都挂在 `body` 下，故 `.rl-theme-modern` 作为**后代选择器前缀**天然命中主界面与全部弹窗 —— 一处挂载全覆盖，且**新增弹窗自动继承**（原方案宣传的优点得以保留）。

**实测依据（计划阶段核查）**：16 个 Modal 中**仅 4 个**持有 `plugin` 引用（CalendarDay/Entry/Excerpt/GameSession），其余 12 个连 `settings` 都取不到 —— 走基类方案需改 16 个文件的继承链，成本远超收益，且属 P1 风险。`body.theme-light` / `body.theme-dark` 是 Obsidian 既有机制，插件在其上挂自有类由 `.rl-hide-scroll` 先例证明无副作用。

**其中 3 个属排除范围**（`PdfReaderModal` / `ReaderModal` / `VideoPlayerModal`）：仍会自动获得 `--rl-t-*` 令牌，但通过 `.rl-theme-modern .modal.rl-reader-immersive { border-radius: 0; box-shadow: none; }` 显式排除，维持沉浸式外观。

### 3.4 页签（唯一的组件内结构分支）

页签是本设计中**唯一**需要在组件内分支的组件，因为两套主题的**结构不同**（不只是参数不同）：

| | 主题 A（原生） | 主题 B（现代） |
|---|---|---|
| 容器 | `.rl-tabs`（透明 + 底部通栏细线） | `.rl-tabs`（胶囊容器 + 内阴影） |
| 图标 | 保留（lucide 图标 + 文字） | **去掉，纯文字**（用户裁定 3a） |
| 选中态 | 按钮自身 `border-bottom` 蓝线 | **独立 `<span class="tab-ind">` 滑动指示器** |
| 按钮内边距 | 现有（图标存在时的左右距离） | 加大（纯文字需靠 padding 撑出可点区域） |
| DOM 差异 | 无额外节点 | 无图标节点 + 多一个指示器节点 + JS 定位 |

**实现方式**：`HomeView.svelte` 收 `theme` prop，模板内 `{#if theme === 'modern'}` 分支渲染指示器节点；图标渲染处同样按主题条件渲染。

```svelte
<button class="rl-tab" class:on={...}>
  {#if theme !== 'modern'}<span class="rl-tab-ico">{@html tabIcon(t)}</span>{/if}
  <span class="rl-tab-txt">{tabLabel(t)}</span>
</button>
...
{#if theme === 'modern'}<span class="tab-ind" style="transform:{indStyle}"></span>{/if}
```

**窄栏溢出处理**：6 个纯文字页签在窄侧栏下可能超出容器宽度。**不允许压缩字号或换行**，改为容器 `overflow-x: auto` + `scrollbar-width: none` 横向滚动；指示器定位取 `scrollLeft` 参与计算。实现后须在 ~320px 宽侧栏实测。

> **为什么不给页签也用变量**：变量能改变颜色和圆角，但**变不出一个新的 DOM 节点**（滑动指示器），也**删不掉一个节点**（图标）。两者都必须走结构分支。

### 3.5 设置页入口

在「外观」区（现有「隐藏插件内滚动条」上方）新增：

```
外观
  界面主题      [原生 ▾]            ← 新增，选项：原生 / 现代
               原生：保持 Obsidian 克制风格（默认）；现代：更圆润的卡片与分段式页签。
  隐藏插件内滚动条  [开关]
```

- 控件：`addDropdown`（与项目既有下拉一致，比 toggle 更适合多于两选项的场景，为将来第三套主题留位）
- 选项文案：**「原生」/「现代」**（用户裁定 1a，不用「经典」）
- 默认值：`'native'`
- 切换后**即时生效**：调用主题应用函数重新挂类，**不弹 Notice**（用户裁定 2a）

### 3.6 历史遗留清理：`colorTheme`

**现状**：`colorTheme: 'colorful' | 'mono'` 处于半拆除状态 —— 类型与 `MediaList` 的 `colorful` 分支代码仍在，但 v0.4 起设置项已删、`main.ts:175` 硬写 `'mono'`。

**⚠️ 原表述有误，已修正（2026-09-12，实现阶段实测推翻）**：本节初稿称该硬写行是「死代码，删除后行为不变」，依据是「它是唯一写入点」。**这个推理方向是反的** —— 「唯一写入点」恰恰意味着**磁盘上任何历史遗留的 `colorful` 失去了唯一的纠正者**。实测证据链：

1. `main.ts` 的 `Object.assign({}, DEFAULT_SETTINGS, await this.loadData())` —— **磁盘值优先于默认值**，`colorTheme: "colorful"` 会被原样保留，**不会**落回默认的 `'mono'`。
2. 「色彩主题：彩色（类型色条+状态五色）/ 单色切换」是 **v0.0.1 的正式已发布功能**（见 `Project-Rule/CHANGELOG.md` v0.0.1 节），v0.4 才移除入口 → 存量用户真实存在。
3. v0.4 起设置页已无该入口，`saveSettings` 的失效判据也不含 `colorTheme` → **删掉硬写后用户无法自救**。
4. 出口是活的：`HomeView.ts:62/74` 把值透传给 `MediaList.svelte:558` 的 `{#if colorTheme === 'colorful'}`；且两个 Svelte prop 的**默认值本身就是 `'colorful'`**（`HomeView.svelte:78`、`MediaList.svelte:46`）。

**结论**：该行**不是死代码，是老用户数据的唯一纠正点**。表现会是「升级 1.0.3 后突然冒出类型色条」，属用户可见回归。

**处理**（`append-only` 原则下的安全做法）：

| 项 | 动作 | 理由 |
|---|---|---|
| `MediaList` 的 `colorful` 分支与 `TYPE_COLORS` 色条渲染 | **原样保留，本次一行不改** | 类型色条属**第三个维度**（色彩策略），不属本设计范围；改了会让本次改动面失控 |
| `main.ts:175` 的 `this.settings.colorTheme = 'mono'` | **保留该行，仅改写注释语义** | 从「死代码清理」改述为「**迁移兜底**」—— 强制定为 `'mono'` 以确保彩色分支永不被激活。删除会引入老用户可见回归（见上） |
| `Settings.colorTheme` 字段与 `DEFAULT_SETTINGS` | **保留**，不改类型不加值 | append-only；旧数据兼容 |
| 设置页 | **不新增** `colorTheme` 入口 | 本次只加 `uiTheme`，不把第三个维度拉进设置页 |

**新增字段**：
```ts
/** 界面主题：native 原生（默认）/ modern 现代 App 风 */
uiTheme: 'native' | 'modern';
```

## 4. UI-GUIDE 修订提案：主题 B 豁免清单

UI-GUIDE §1 明令禁止「阴影堆叠、渐变、圆角夸张、网页感」。主题 B 的设计与其中部分条款冲突。
**不默默违反**，而是在 UI-GUIDE 新增 §6「主题 B 豁免清单」，逐条列出允许的偏离：

| 被豁免的规则 | 主题 B 的具体表现 | 豁免理由 |
|---|---|---|
| 禁止阴影堆叠 | 卡片双层投影、弹窗双层投影 | 现代风靠阴影建立层级，这是该风格的**定义性特征**而非装饰 |
| 禁止圆角夸张 | 圆角 6→16px、控件全圆 99px | 同上 |
| 禁止网页风动画 | 页签指示器滑动（`.3s` 弹性缓动） | 滑动指示器是分段控件的**标准交互**，非炫技 |
| 禁发光 | 输入框聚焦柔光环 | 属**可访问性反馈**（聚焦可见），非装饰性发光 |

**豁免的边界（必须写明，防止无限扩张）**：

- 豁免**仅适用于 `.rl-theme-modern` 作用域内**；主题 A 与任何全局样式**仍适用原规范**。
- 豁免**不含**：渐变填充、3D 倾斜、emoji 图标、呼吸动画、`!important`。
- 主题 B 的**文字对比度仍须满足 §2.1 的 AA 门槛**（阴影与圆角可豁免，可读性不可）。
- 新增豁免项须经用户确认后写入本节。

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 令牌漏引用导致主题 B 局部不生效 | **P1** | 判定口诀：**某处不生效 = 该处值仍是硬编码**。逐个 `grep -c "border-radius: [0-9]"` 清零后构建核对；产物加反向断言守住 |
| scoped 特异性使个别变量失效 | P1 | **本质同上一行**：scoped 规则直接写死值（`border-radius:6px`）时变量无法穿透。解法一律是「把写死值改为 `var(--rl-t-*, 原值)`」，而非提高外层选择器特异性 |
| 主题 B 观感在浅色下失衡 | P2 | 演示页已做浅色/深色双验；实装后两主题 × 两明暗 逐一核对 |
| `colorTheme` 解除硬写后行为变化 | P2 | 不改渲染分支，仅去掉覆盖语句；`normalizeUiTheme` 兜底 |

## 9. 开放问题（已确认 — 2026-09-12 用户裁定）

1. **设置项文案 → 「原生 / 现代」**（用户选 A）

## 方案修订记录

**修订 1（2026-09-12，计划阶段）—— 废弃 `RlModal` 基类方案，改 `document.body` 单点挂载**

原文 §3.3 提出新建 `RlModal extends Modal` 共享基类，让 16 个 Modal 统一继承以挂主题类。计划阶段实测核查后废弃。

| | 原方案（`RlModal` 基类） | 新方案（`body` 单点挂载） |
|---|---|---|
| 触碰文件 | 16 个 Modal + 1 个新基类 | **0 个 Modal**，只改 `main.ts` |
| 可行性前提 | 每个 Modal 能取到 settings | 无需（`body` 全局可见） |
| 新增弹窗自动覆盖 | ✅（继承即得） | ✅（后代选择器即得） |
| 风险等级 | P1（继承链改造） | P2（挂一个类） |

**废弃依据**：16 个 Modal 中**仅 4 个**持有 `plugin` 引用（CalendarDay/Entry/Excerpt/GameSession），其余 12 个连 `settings` 都取不到 —— 需为挂一个类而改 16 个文件的构造路径，成本与风险都远超收益。且 Obsidian 所有 Modal 都挂在 `body` 下，`.rl-theme-modern` 作后代选择器前缀天然覆盖，**原方案的「自动继承」优点完全保留**。

**连带影响**：
- §5 文件改动清单：`src/modals/*.ts`（16 个）从「迁移基类」改为 **「一行不改」**。
- §8 风险表：原「`RlModal` 继承链改造」风险项删除，替换为「令牌漏引用」风险（新方案下的真实首要风险）。
- 页签**仍**保留组件内结构分支（`{#if uiTheme === 'modern'}`）—— 它是唯一必须增删 DOM 节点的地方，与挂载点方案无关。

**实施计划**：`docs/superpowers/plans/2026-09-12-1.0.3-ui-theme.md`
