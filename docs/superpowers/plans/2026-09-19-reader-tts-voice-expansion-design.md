> 本文按项目「需求交付流程」三步走产出：① 金标准检索 ② 2–3 个可选方案 ③ 模块规划。

## 1. 现状勘察（先摆事实）

**① 音色从哪来 —— 完全取决于操作系统。**
现行实现走 **Web Speech API**（`window.speechSynthesis`）：`TtsService` 只做一件事 —— `getVoices()` 拿系统装着的那几个语音，`pickVoiceIndex` 优先「语言匹配 + 本地」。所以：

- **音色数 = 系统装了哪些语音**，插件一个也加不了；
- **Electron 拿不到 Edge 的在线自然音色**（那批「晓晓/云希」是 Edge 浏览器自己的在线能力，不是系统 SAPI 语音）⇒ 桌面端多半只有 2–5 个中文旧式拼接音；
- **移动端本来就不可用**（已在按钮上置灰）。

**② 现有 UI 还没把系统语音榨干。** 右键弹窗是一个**平铺列表**（`名称 · 语言`，语音 ≥2 个才显示），没有：按语言分组 / 试听 / 音调（pitch）/ 记住上次选择（只有语速会记）。

**③ 两条项目约束会在选型时反复出现：**
- **体积敏感**：`main.js` 现 **4,114,422B**，其中内联 PDF.js 是最大单项（历史口径约占 61%）⇒ ⛔ 不该为一个朗读功能再塞进大包；
- **已有 AI 通道单一真源**：设置页的「AI集成」已管着 智谱 / DeepSeek 两家 key（`main.chatCompletion` + 纯模块 `build*Body`），**新音源最好复用同一套 key 管理与 UI 范式**。

## 2. 金标准检索（生态里别人怎么做）

| 参照 | 做法 | 对我们的启示 |
|---|---|---|
| **`obsidian-aloud-tts`**（生态最全，社区版名 **Voice**，69★ / 47 releases） | **8 家云端 provider**（OpenAI、Gemini、ElevenLabs、Azure、Polly、Hume、**MiniMax**、**OpenAI 兼容（advanced）**），全部要 key；**逐句流式播放 + 库里缓存音频 + 后台预取**；另支持**手机上锁屏播放** | 「多 provider 注册表 + 逐句合成 + 缓存」是这个功能的成熟骨架；其中 **OpenAI 兼容口**最省事（一个适配器吃多家） |
| **`edge-tts`**（rany2，社区事实标准） | 复刻 **Edge 浏览器「大声朗读」** 的在线接口：**322 音色 / 74 语言 / 中文约 9–14 个（含方言）**，**免 key、免注册**；代价 = 非官方接口（随时可能变）+ 必须联网 | 唯一「不花钱又多音色」的路子；但**需在插件里做 WebSocket 客户端**（渲染进程可用浏览器 `WebSocket`，但接口要 `Sec-MS-GEC` 等查询参数，是否被 Origin 校验拦需**先探针验证**） |
| **智谱 GLM-TTS**（`/api/paas/v4/audio/speech`，model `glm-tts`） | **7 个系统音色**（彤彤 / 锤锤 / 小陈 / 4 个「动物圈」角色音）+ **声音复刻**（上传 3–10s 参考音频 → 自定义音色）；单次上限 **1024 字符**（≈ 我们 1–8 句，天然匹配）；超拟人质量；默认带 AI 水印（可关） | 🔴 **我们已经有智谱 key**（AI集成里配过）⇒ 接入成本最低；「复刻」能把音色变成**无限** |
| **硅基流动**（`/v1/audio/speech`，OpenAI 兼容） | 一个口吃多家开源模型（CosyVoice2 / fishaudio / GPT-SoVITS…）；**8 个预置音色** + 用户上传音色（需实名）+ 动态克隆；文档明确「音色支持系统预置 / 用户预置 / 动态克隆」 | 「一个适配器多引擎」的现成范式；有免费额度（具体数字待核实） |
| **Piper / sherpa-onnx / MeloTTS**（本地离线） | 纯本地 ONNX 推理、断网可用、零费用；但**中文音色极少**（典型就 `zh_CN-huayan-medium`、`xiao_ya` 等 1–3 个），且要用户自行下载 **几十~上百 MB** 模型 + 二进制 | 与「音色更多」的目标**方向相反**；插件也不该自带大模型 ⇒ 只适合做「隐私优先」的可选档 |

**结论（供决策）**：想要「音色明显更多」，必须**把合成搬到云端**（B/C 两条）；系统语音那条路（A）怎么优化都只有 2–5 个音色，但它能立刻改善**挑音色的体验**，且零成本零风险。

## 3. 候选方案

### 方案 A —— 榨干系统语音（零成本、零风险、音色数不变）
把现有的平铺列表做成一个像样的「语音选择器」：

- 按语言分组（`中文 / 英语 / 其它`）+ 本地/在线标记；
- **试听**按钮（`speechSynthesis` 本地试听，不花钱）；
- **音调（pitch）滑条**（与语速并列，Web Speech API 原生支持）；
- 记住上次选中的语音（现在只有语速会记）；
- 引导文案：Windows「设置 → 时间和语言 → 语音」可安装更多语音包（含第三方 SAPI 语音）。
- ⚠️ 天花板明确：**音色数量不会增加**，音质仍是旧式拼接音。

### 方案 B —— 接 Edge「大声朗读」在线接口（免 key、音色 300+）
- 音色：**zh-CN 约 9–14 个**（晓晓 / 晓伊 / 云希 / 云扬 / 云健 / 晓辰 + 辽宁等方言），总 322 个 / 74 语言；
- 成本：**0 元**，无注册、无 key；音质为神经语音（明显好于系统 SAPI）；
- 代价 / 风险：
  1. **非官方接口**（社区复刻，微软可随时改）——必须做「失败可回退」；
  2. **需要 WebSocket 客户端**：渲染进程可用浏览器 `WebSocket`，但**必须先探针验证**「插件环境直连是否被 Origin / 鉴权拦」（拦了就得在 Node 侧自己走握手，复杂度上升）；
  3. 必须联网、可能被限流；无 SSML 之外的精细控制（有 rate/pitch）。

### 方案 C —— 复用现有 AI key 接云 TTS（推荐主轴）
在「AI集成」下新增一个 **「语音合成」** 子块，实现**一个 OpenAI 兼容的适配器**（`POST {baseUrl}/audio/speech`，body `{model, input, voice, response_format}`）：

- **首推智谱 `glm-tts`**：key 已经配好、无需新注册；7 系统音色 + **声音复刻**（音色可无限扩）；单次 1024 字符与「逐句朗读」天然匹配；
- 同一适配器**顺带支持**硅基流动 / 本地 `openedai-speech` / 任何兼容服务（只换 baseUrl + 模型名），**一次实现多家可用**——这正是金标准插件的做法；
- 需要做好的三件事：**逐句合成 + 后台预取下一句**（否则每句之间会有明显空档）、**音频缓存**（省费用、支持离线重听）、**失败回退系统语音**（不把「没网」变成「不能读书」）；
- 代价：按字符计费（各家的免费额度 / 单价以控制台为准，**待核实**）；需联网。

### 方案 D —— 本地离线神经 TTS（Piper / sherpa-onnx）
- 隐私最好、零费用、断网可用；**但中文音色只有 1–3 个**，且需用户自备几十~上百 MB 模型与可执行文件 ⇒ 与「音色更多」相悖；建议**只在 C 落地后作为可选档**（配置一个「外部命令」路径即可）。

## 5. 建议（我的取向）

**A + C，C 先落智谱。** 理由：

1. **A 是纯增量的体验修缮**，零风险，顺手就该做（试听 / 音调 / 分组 / 记住选择）；
2. **C 用现有 key 就能把音色从「2–5 个」抬到「7 个 + 可复刻」**，质量跃升，且**架构上是「一个 OpenAI 兼容适配器」**——将来想换硅基流动 / 加第二家只是配置问题；
3. **B 留作「不花钱」的第二音源**，但**先花一次探针成本验证可行性**再决定是否真做（官方接口随时变，不值得赌在它上面）；
4. **D 不做**（方向相反，且与体积约束冲突）。

## 7. 模块规划（若 D-1 选 Ⓐ A+C，按可独立执行 / 可测的粒度拆）

- **M0 探针（先做，成本最低）**：`_probe_tts_cloud.cjs` —— 用测试库里的智谱 key 实际打一次 `/audio/speech`，确认：能否拿到二进制（WAV/PCM）、单句延迟、1024 字符上限的真实行为、水印开关是否影响播放、`requestUrl` 取 arrayBuffer 是否顺。⚠️ 这一步决定 C 的可行性，**在写任何服务之前做**。

- **M2 纯逻辑（TDD）**：`pure/ttsQueue.ts` —— 逐句队列与**预取窗口**（当前句播放时合成下一句）、失败重试与回退决策（纯函数，注入「合成器」与「播放器」两个接口）。

## 11. C 段实施规格（硅基流动 · 2026-09-19 检索核定）

### 11.1 API 事实（以官方文档为准，非凭记忆）

```
POST https://api.siliconflow.cn/v1/audio/speech
Headers: Authorization: Bearer <key> · Content-Type: application/json
Body:
  model           "FunAudioLLM/CosyVoice2-0.5B"   ← 中文最优（另有 fishaudio/fish-speech-1.5、IndexTTS-2）
  input           待合成文本（单句 ⇒ 天然远低于上限）
  voice           "FunAudioLLM/CosyVoice2-0.5B:alex"  ← 🔴 必须带**模型名前缀**
  speed           0.25 ~ 4.0（默认 1.0）          ← 我们 UI 的 0.5~2 落在范围内，可直接透传
  gain            -10 ~ 10 dB（默认 0，音量非音调）
  response_format mp3（默认）/ wav / pcm / opus
  sample_rate     mp3 → 32000 | 44100（默认 44100）
返回：**二进制音频字节**（inline，非 JSON）⇒ 走 `requestUrl({ responseType: 'arraybuffer' })`
```

**8 个系统音色（固定，无需联网获取）**

| voice id | 中文标签 | 性别 |
|---|---|---|
| `alex` | 沉稳男声 | 男 |
| `benjamin` | 低沉男声 | 男 |
| `charles` | 磁性男声 | 男 |
| `david` | 欢快男声 | 男 |
| `anna` | 沉稳女声 | 女 |
| `bella` | 激情女声 | 女 |
| `claire` | 温柔女声 | 女 |
| `diana` | 欢快女声 | 女 |

### 11.2 四条硬约束（云音源特有）

1. 🔴 **`voice` 必须带模型名前缀** —— 传裸 `alex` 会被拒。音色 id 在真源里就存**全称**，UI 只显示中文标签（选项 `value` 用全称）。
2. 🔴 **不支持 `pitch`（音调）** —— 云侧只有 `speed` + `gain`（音量）。故云音源下「音调」行不能留（详见 D-10）。
3. 🔴 **返回是二进制不是 JSON** —— 绝不能走 `parseTranslateResponse` 那条 JSON 通道；复用既有 `responseType: 'arraybuffer'` 先例（main.ts 图床下载同款）。
4. 🔴 **按字符计费** ⇒ 缓存与预取都要克制（D-13）；失败不能无限重试（否则烧额度）。

### 11.3 接入架构（关键：**高亮 / 滚动 / 串音守卫一行不动**）

```
TtsService  ← 不变：切句 / 队列 / 逐句高亮 / 居中没有滚动 / gen 代数守卫 / 按钮态 / 起读点
     │ 经由 SpeechEngine 接口（新增，薄）
     ├── SystemSpeechEngine   ← 把现有 speechSynthesis 那段**原样搬入**
     └── CloudSpeechEngine    ← 合成(HTTP arraybuffer) + 播放(Audio + blob) + 句级缓存 + 预取
```

```ts
interface SpeechEngine {
    /** resolve 'ended' = 读完；'cancelled' = 被取消（由 TtsService 的 gen 守卫裁决是否继续排队） */
    speak(text: string, opts: { rate: number; pitch: number; voice: string | null }): Promise<'ended' | 'cancelled'>;
    cancel(): void;
    voices(): TtsVoiceLite[];   // 系统引擎异步补；云引擎静态
    dispose(): void;
}
```

**为什么这样拆**：高亮 / 滚动 / 起读点 / 代数守卫是本功能最贵也最稳的部分（#340–#342 反复打磨），换音源只该换「怎么把这一句发出去」。⇐ 这也是「最小改动」取向的落点。

### 11.5 模块规划（覆盖 §7 的 M1–M6）

- **M1 纯逻辑（TDD）** `pure/ttsCloud.ts`：`CLOUD_PROVIDERS`（硅基流动：baseUrl / model / 音色全称表 + 中文标签 + 性别）、`speechEndpointUrl(baseUrl)`、`buildSpeechBody({text, voice, rate, model})`、`cloudVoiceGroups(curVoice)`（男声／女声两组）、`normalizeCloudVoice(id)`、`classifySpeechError(status, bodyText)`（401 / 429 / 余额 / 超长 / 其它）。**零 DOM 可单测。**
