## 0. 结论速览

| 项 | 结论 |
|---|---|
| 数据 | 新字段 `related?: RelatedLink[]`（append-only）；`RelatedLink = { id: string; label?: string }` |
| 落库 | `catalog.ts normalizeEntry` 同步白名单（红线 2）—— 非数组丢、逐项校验、去重、脏值不落 |
| 关系词 | 自由文本（下拉只做**建议**，不设白名单）；留空 = 「关联」 |
| 双向 | **不写进对方数据**，渲染时由纯函数扫全库算入边；关系词按取反表镜像，**表外一律「被关联」** |
| 图谱 | 放射状 SVG；当前条目居中、关联条目围一圈；**布局算法在纯模块**（只出节点 + 边 + 角度 + 半径），坐标不写死在组件里 |
| 上限 | **不设硬上限**；半径自适应 + 节点多时标签悬停才显示 |
| 切条目 | `EntryModal` 走既有 `mountForm` 重建；**表单脏时才弹确认**（不脏直接切） |
| 失效引用 | 目标 id 查不到 ⇒ **渲染时过滤** + 角落提示「N 条关联已失效」；⛔ **不删数据** |

## 1. 口径边界（写在最前，防将来误扩）

- **只做手动关联字段**，⛔ **不动笔记里的 `[[双链]]`**（不解析、不生成、不参与图谱）。理由：笔记会被 `writeNote` 重写，把图谱信息挂在笔记文本上 = 与重写耦合；且双链的语义是「提到」不是「是什么关系」。
- ⛔ **不写反向数据**。A→B 的反向**只在渲染时算**：摘掉 A 那条，B 那边自动消失，**不会留脏引用**（这是选「渲染时算」而非「写入时双向写」的全部理由）。
- ⛔ **不做自动发现/推荐**（不按标题相似度猜、不按标签聚类）。图谱 = 用户手填关系的镜子。
- ⛔ **不做全库大图谱**（只画「以当前条目为中心的一圈」）。全库力导向图是另一个命题，且与「编辑弹窗里的小节」这个落点不匹配。

## 2. 数据层

### 2.1 类型（`src/data/types.ts`，append-only）

```ts
/** 手动关联：指向另一条条目的 id + 自由关系词（「原唱」/「翻唱」/「改编」…；留空 = 普通「关联」） */
export interface RelatedLink {
    id: string;
    label?: string;
}

export interface MediaEntry {
    // …既有字段…
    /** 手动关联条目（#634）；缺省 = 无关联（老条目零迁移） */
    related?: RelatedLink[];
}
```

### 2.2 落库白名单（`src/data/catalog.ts` 的 `normalizeEntry`）

红线 2：新增字段**必须**同步白名单，否则保存即静默丢弃（本仓踩过多次）。

```ts
related: normalizeRelated(raw.related),
```

`normalizeRelated` 口径（**唯一收口点**）：

| 输入 | 输出 |
|---|---|
| 非数组（含 `undefined` / `null`） | `undefined`（⛔ 不落 `[]` —— 空数组与「没有」在存储上等价，但多一个键会让 `data.json` 无谓膨胀） |
| 数组里非对象项 / `id` 非字符串 / `id` trim 后空 | **丢该项**（⛔ 整批不废 —— 一项脏不该吃掉用户手填的其它项） |
| `label` trim 后空 | 落 `undefined`（⛔ 不落 `''`：`''` 会让「留空 = 关联」的判据在渲染侧要判两次） |
| 同 `id` 重复 | **后写的赢**（与 #427 断点续传存档同一口径） |
| `id` 指向自己 | **丢**（自环在图上没有意义，且会让「点节点」变成「切到自己」） |
| 归一后空数组 | `undefined` |

### 2.3 不做迁移

老条目无 `related` 键 ⇒ 读时 `undefined` ⇒ 空图。**不需要迁移函数**（与 `wallColumns` / `cardFieldsByType` 同一套「缺省即没有」的口径）。

## 3. 纯模块 `src/pure/relatedGraph.ts`

> 🔴 **新增纯模块必须同步 `vitest.config.ts` 的 alias 表**（红线 6）。

### 3.1 导出

| 导出 | 职责 |
|---|---|
| `RelatedNode` | `{ id, title, type, label: string, mirror: boolean }` —— 图上**一个节点**（`label` 已算好取反，渲染侧不再判）；**mirror = 这条是「别人挂了我」** |
| `RelatedGraph` | `{ nodes: RelatedNode[]; invalid: number }` —— **一次算全**（节点 + 失效计数） |
| `normalizeRelLabel(raw: unknown): string \| undefined` | trim + 空 ⇒ undefined + 长度上限（防巨型文本进 SVG） |
| `invertRelLabel(label: string \| undefined): string` | 取反表命中 ⇒ 反义词；表外 / 空 ⇒ **「被关联」** |
| `REL_LABEL_SUGGESTIONS: string[]` | 录入侧下拉建议（原唱/翻唱/改编/原作/续作/前作/同曲/现场版）；⛔ **只是建议**，不是白名单 |
| `RADIAL_ALT_MIN` | 启用交替半径的最小节点数（**6**） |
| `GRAPH_MAX_READABLE` | 标签「默认显示」的节点数门槛（**8**；超过转悬停显示。取 8：象形稿 6 条可读、12 条已密，8 是两者之间） |
| `MIN_NODE_R` | 节点圆半径下界（**4**） |
| `collectRelated(entry, allEntries): RelatedGraph` | **出边 + 入边**合并、取反、去重、失效过滤（唯一算法入口） |
| `graphLayout(count, opts)` | **只出几何**：每个节点的角度 + 半径 + `labelsVisible`；⛔ 不产出坐标（坐标在组件里由角度/半径换算，便于单测纯几何） |

### 3.2 镜像与取反（裁定 ③）

- A 的 `related` 里有 B（label「翻唱」）⇒ **A 的图**上 B 显示「翻唱」。
- **B 的图**上 A 显示 `invertRelLabel('翻唱')` = **「原唱」**；A 侧 label 为空 ⇒ B 的图上显示 **「被关联」**。
- 取反表**成对且对称**（`原唱↔翻唱`、`改编↔原作`、`续作↔前作`）；表**外**一律「被关联」（⛔ 不猜、不做模糊匹配 —— 猜错比不猜更坏）。
- 同一条既有出边又有入边（互相挂）⇒ **按出边优先**合并成一条边（图上不出现两条重线）。

### 3.3 布局（裁定 ⑥：不设硬上限）

`graphLayout(count, { width, height })` 只负责算数，**SVG 由组件画**：

- 角度：`2π × i / count`（等分），起始 −90°（12 点方向）。
- 半径：
  - 基数 `R = min(width, height) / 2 − padding`；
  - `count ≥ RADIAL_ALT_MIN`（6）⇒ **交替半径**（`R` / `R × 0.8`）错开标签；
  - **不设节点数硬上限**：`count` 大 ⇒ 半径仍取 `R`、**节点圆变小**、标签转悬停显示。
  - ⚠️ 节点圆半径有**下界**（不小于 `MIN_NODE_R`），低于下界就交由「标签悬停显示」+ 重叠可接受（⛔ 不缩到看不见、⛔ 不静默丢节点）。
- 标签默认显示判据 = `count <= GRAPH_MAX_READABLE`（**8**：象形稿 6 条仍可读、12 条已密）。
- 🔴 **退化安全**：`count === 0` ⇒ 返回空数组（组件走空态）；`width/height` 非有限数 ⇒ 回落常量；⛔ 不产出 `NaN` 坐标（`NaN` 进 SVG 属性 = 元素静默不渲染，极难排查）。

## 4. 接线

### 4.1 录入区（`EntryForm.svelte`）

- 位置：**「个人评语」之下、「相关链接 / 观看链接」之上**（与笔记章节顺序一致：基本信息 → 简介 → 评语 → **关联** → 链接）。
- 形态：chips 一行（每条 = 关系词徽标 + 标题 + ✕）+「＋ 添加关联」按钮。
- 「＋ 添加关联」⇒ 打开**库内条目搜索**（输入即过滤、方向键选、回车挂上）。
  - 🔴 复用既有搜索入口形态，⛔ **不发网络请求**（只搜本库条目 —— 关联的是「我库里的条目」）。
  - 已挂过的条目**从候选里隐藏**（防重复挂）。
- 关系词：点 chip 上的词**就地编辑**（`<input>` 失焦提交）；留空 ⇒ 不显示徽标。
- 两处联动：`pageKey` 类的东西**不存在**（这是表单内部 state，与视图筛选无关）。

### 4.2 图谱小节

- 标题「**关联图谱 · N 条**」，可折叠，**默认展开**（与象形稿一致）。
- 节点：当前条目居中（实心 + 标题）；关联条目围一圈。
  - 节点文案：**条目标题**；标签（关系词）按 §3.3 判据显示或悬停才显示。
  - **mirror 节点视觉可区分**（空心描边 vs 实心；与象形稿「当前条目实心」不冲突 —— 中心那个才是实心强调色）。
- 边：中心 → 节点连线；悬停某节点 ⇒ 该边加粗、其余淡出（看关系时不糊成一片）。
- **点节点** ⇒ `onOpenRelated(id)`（裁定 ②）。
- 空态：**不画空图**，直接把「＋ 添加关联」摆出来（象形稿 §2 空态块）。
- 角落提示：失效引用 `N > 0` 时显示「**N 条关联已失效**」（⛔ 不删数据、不弹窗）。

### 4.3 切条目（裁定 ②⑤）

- `EntryModal` 新增 `onOpenRelated(id: string)`：
  1. **脏检查**（`EntryForm` 导出脏标志）—— 脏 ⇒ `ConfirmModal`「当前改动未保存，仍要切换吗？」；取消 ⇒ 什么都不做。
  2. 切换 = **`mountForm(新条目, lrc)` 重建**（复用 #632 的机制：Modal 外壳 / `contentEl` / `onOpen` 那套都不碰）。
  3. 🔴 **必须同时把 `this.entry` 换成新条目**（现为 `private entry?: MediaEntry` 只读语义）—— 漏了这一步，界面上是 B 的字段、保存时却走 `service.update(A.id)`，**把 B 的内容写进 A**。
  4. 重建前**重置 `this.entry`** ⇒ 后续「更新笔记」按新 id 走；`saved` / `downloadedPosters` 等会话字段口径不变。
- ⚠️ 切换后**没有「返回上一条」**（裁定 ② 的字面含义是「切过去继续编辑」）。若将来要返回，需一条浏览栈 —— **本批不做**，登记为待议。

### 4.4 笔记侧

- `noteGenerator` 属性表新增一行「**关联**」（有 `related` 才出；渲染成 `- 关系词：[[目标标题]]` 形态，与既有 wikilink 口径一致）。
- 🔴 **纳入重写保留区**（与 `links` / `notes` 同级）：否则用户手改笔记后 `writeNote` 会把它抹掉 —— 本仓在 #396（LRC 歌词）踩过同款。

### 已知排雷（本仓既有教训，落码时逐条对照）

1. **注释会进产物** ⇒ 源码级反向守卫**先剥注释**（#628 踩过）。
2. **锚必须进方法体切片** —— 同款代码常在别处（#631 踩过）。
3. **Svelte 4 模板不许 `as Xxx` / `!` / `bind:value={arr[i]}`**（AGENTS.md 坑点表）。
4. **Svelte 4 scoped 重复次数 = 最大 compound 数** ⇒ 新样式**复合选择器 ≤2**（#624 踩过，当时 29 条 FAIL）。
5. **`formatter`/`decode()`**：断言脚本有 `decode()`，中文锚可用；自写探针没走 decode 会误判「中文锚不住」。
6. **模板里 `{#if}` 删改后必须整体成对** —— 留下孤立 `{/if}` ⇒ Svelte 编译失败 ⇒ 产物没更新 ⇒ **断言拿旧产物判绿**（#624 的假绿）。
7. **新纯模块必须进突变 runner**，否则那几条**假绿**（#629 踩过）。
8. **`<input type="number">` 的 `bind:value` 会让变量运行期变 `number`**，与 TS 看到的 `string` 初值不符 ⇒ 运行期 `TypeError` 被 promise 吞掉（#436b 踩过）⇒ 本批所有数字/文本输入走 `parseSeriesIndexInput` 同款**收口函数**。
