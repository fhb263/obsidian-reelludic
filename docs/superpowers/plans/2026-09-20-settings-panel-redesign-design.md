# 设置面板重设计 · 设计规范稿

> 日期：2026-09-20 | 状态：**待裁定**（决策点见 §6，未施工）
> 触发：用户反馈「树状导航层级模糊、分组标题与子菜单区分度不够、纯文本列表单调、空间利用率低」
> 交付物：本规范稿（结构选型 + 亮/暗双主题视觉规范 + 图标映射 + 裁定清单）

---

## 0. 一句话结论

**「层级模糊」不是字重/字号问题，是「用同一根垂直轴承载 6 个同级标题」的必然结果** —— 在单一滚动列里，无论怎么调字号，用户仍然分不清「我现在在哪一层」。真正的解法是**换一根轴**：把「页」的切换从垂直堆叠改成**水平分栏**，让层级由**位置**承载，字号只负责「组标签」的弱化。

因此本稿主推 **方案 A（左右分栏）**，并把 **方案 B（手风琴）** 保留为**窄屏降级形态**（二者共享同一套图标、行高、变量规范，不是两个设计）。

## 1. 现状盘点（对 `src/Settings.ts` 实测）

### 1.1 真实结构：**6 个一级标题 + 5 个可折叠子分组 + 约 31 行**

| 一级标题（`setHeading()`） | 子分组（`createGroupSection`，可折叠） | 行数 |
|---|---|---|
| **数据源管理** | 数据源启用 | 按 5 个分类（书籍/影视/动画/音乐/游戏）列出若干开关行 |
| | 数据源凭据 | **11 行**（6 个需 Key 源 + 5 个免 Key 源） |
| **AI集成** | AI服务 | 4 行（朗读音源/翻译服务/总结服务/搜索服务） |
| | API凭据 | 各 AI 服务一行 |
| | 语音合成 | 若干 |
| **外观** | —（无子分组） | 1 行（隐藏插件内滚动条） |
| **实验性功能** | —（无子分组） | 2 行 |
| **数据管理** | —（无子分组） | 5 行（媒体库目录/笔记表格/导出备份/下载封面/附件清理） |
| **关于** | —（无子分组） | 区块（支持文案 + 2 按钮） |

**关键观察**：

1. **结构极不对称** —— 前两个标题（数据源管理 / AI集成）占了 **5 个子分组 + 约 20 行**（≈ 总量的 2/3），后四个标题（外观/实验性功能/数据管理/关于）**完全没有子分组、合计仅 8 行**。全量平铺时，前者把后者挤到视口外。
2. **子分组的「分级」是错的** —— 「数据源启用」与「数据源凭据」并列在实际语义上并不是「组」，而是**同一件事的两个阶段**（先决定用哪些源、再填凭据）。它们之所以成为组，是因为行数太多不得不折叠。
3. **「关于」是个异类** —— 它不是设置项，却和设置项平级。

### 1.2 「层级模糊」的三条根因

| # | 根因 | 实证 |
|---|---|---|
| ① | **一级标题与子分组标题字号只差 1px** | 原生 `setHeading()` = 14px/600/`--text-normal`；`rl-svc-group-title` = 13px/600/`--text-normal`。字重、颜色**完全相同**，只差 1px 字号 ⇒ 人眼无法建立层级 |
| ② | **一级标题「不折叠」而子分组「折叠」，但视觉上无标记** | 一级是原生 heading（无箭头、无 hover 反馈），子分组有 ▸ 箭头 + hover 底色 ⇒ 用户学到的是「有箭头=可点」，于是**以为一级标题点不动/是坏的** |
| ③ | **全部落在一根垂直轴上** | 6 个一级 + 5 个子分组 = **11 个标题块**在同一条滚动流里。标题与标题之间的「空行 + 灰字」重复出现 11 次，视觉上退化成「一列长短不一的灰字」——这正是用户说的「纯文本列表显得单调」 |

### 1.3 硬约束（实测）

| 约束 | 实测值 | 后果 |
|---|---|---|
| 最低支持版本 | `manifest.json` → **`minAppVersion: 0.15.0`** | ⛔ **不能用** Obsidian 1.13+ 的声明式设置页导航（`getSettingDefinitions` 的 `page`）—— 用了就必须升最低版本，影响全部老用户 |
| 平台 | `isDesktopOnly: false` | ⚠️ **必须支持手机**。手机上设置页宽度极窄 ⇒ 左右分栏**必须**有降级形态 |
| 渲染方式 | 命令式 `new Setting(containerEl)`，`display()` 每次重绘 | 结构改造要落在 `display()` 里，不能靠 DOM 打补丁（会被重绘冲掉） |
| 标题文案 | 「数据源管理 / AI集成」被全仓 **6 处路径文案**引用 | ⚠️ **改标题文字须同步这 6 处**（见 §7） |

## 2. 金标准检索结论

### 2.1 官方（Obsidian Plugin Guidelines / API）

- **必须用 `setHeading()` 而非自造 `<h2>`** —— 理由：自造标题元素造成跨插件样式不一致。**本仓已遵守**（`createSectionHeading`）。
- **设置项名称用 sentence case**（"Template folder location"，不是 Title Case）。⇒ 「分组标题全大写」若指**英文大写**，**与官方口径冲突**（见 D-3）。
- 设置控件用原生 `Setting`（`addToggle` / `addDropdown` / `addSlider` …）。**已遵守**。
- 官方 `SettingGroup`（带 heading 的容器）存在，但**没有**官方的「插件设置内部导航栏」API —— 官方给插件的只有一个 `containerEl`。
- **1.13+ 新增声明式设置页**（`getSettingDefinitions()`，`type: "page"` 即是官方版导航页）。⚠️ 本仓 `minAppVersion: 0.15.0` ⇒ 只能作为「未来可选升级」。

### 2.2 社区事实标准

- **Style Settings 插件**（设置型插件里装机量最高之一）用的正是**左右分栏**：左侧分类导航 + 右侧配置详情 + 实时生效。⇒ **方案 A 有社区金标准背书**。
- 有第三方插件（Settings Sidebar Organizer）试图改造 Obsidian **自己的**设置侧边栏，但**只能靠 DOM hack**，作者自己标注「无官方 API、Obsidian 改样式就会坏」。⇒ ⛔ **本插件不要碰 Obsidian 设置外框**，只在**自己 tab 的 `containerEl` 内部**做。
- 社区最佳实践要点（用于核对）：
  - 用内置 CSS 变量，**不硬编码颜色/字体**（`--text-normal` / `--text-muted` / `--text-faint` / `--font-ui-small` / `--nav-item-color-hover` / `--cursor`）
  - 图标用**相对 em 单位**（`width: 0.85em`）+ `align-items: center`，避免绝对像素导致基线错位
  - 侧栏/树结构**模仿原生 `.tree-item` 结构**，用 `flex-grow: 1` 撑开
  - 悬停变化**不要用 `display: none → flex`**（会顶动相邻元素），用 `visibility` 或 `position: absolute`

### 2.3 ⚠️ 对参考材料的核实（两条不成立的）

| 参考材料里的说法 | 实测 | 结论 |
|---|---|---|
| 用 `.tree-item-spacer { flex-grow: 1 }` 撑开 | 该奥类名在 `obsidian.asar` **0 命中** | ⛔ **不要照搬**（本版不存在该类名），自己写 `flex: 1 1 auto` |
| 用 `--nav-item-border-radius` 控制导航项圆角 | 该变量 **0 命中** | ⛔ 不存在 ⇒ 圆角自己写 `border-radius` |
| `getSettingDefinitions` 是「新推荐写法」 | 运行时确实存在（23 命中），但本仓 `minAppVersion 0.15.0` | ⚠️ 可用性与本仓策略冲突，转为 D-2 |

## 3. 方案 A：左右分栏（主推）

### 3.1 象形稿

```
+---------------------------------------------------------------------------+
|  设置 / ReelLudic                                                          |
+---------------------+-----------------------------------------------------+
|                      |                                                     |
|  [i] 数据源管理   <- |   数据源管理                                        |
|  [i] AI集成          |   ==============================================    |
|  [i] 外观            |                                                     |
|  [i] 实验性功能       |   v 数据源启用                                       |
|  [i] 数据管理         |     +-------------------------------------------+   |
|  [i] 关于            |     | 豆瓣                        [已启用  o]     |   |
|                      |     | 作品 / 书籍 / 影视                          |   |
|  168px 固定           |     +-------------------------------------------+   |
|  选中 = 底色 + 左 3px |     | TMDB                        [已启用  o]     |   |
|  强调色竖条 + 强调文字 |     +-------------------------------------------+   |
|                      |                                                     |
|                      |   v 数据源凭据                                       |
|                      |     +-------------------------------------------+   |
|                      |     | 豆瓣 API Key        [________]  [测试]      |   |
|                      |     +-------------------------------------------+   |
|                      |                                                     |
+---------------------+-----------------------------------------------------+
        ^ 导航轴（层级由「位置」承载）      ^ 内容轴（只显示当前页）
```

**对比现状的关键收益**：
- 右侧**一次只显示一页** —— 「数据源管理」页 ≈ 20 行，而不是全量 31 行 + 11 个标题。
- 后四个标题（外观/实验性功能/数据管理/关于）**永远可见**，不再被挤到视口外。
- 一级与子分组的层级差**由左右分栏天然拉开**，不需要靠字号较劲（根因①消解）。
- 「关于」这类异类被隔离到独立页（根因③消解）。

### 3.2 尺寸与状态规格

| 项 | 规格 | 依据 |
|---|---|---|
| 左栏宽 | **168px** 固定（`flex: 0 0 168px`） | 中文最长项「实验性功能」5 字 + 图标 + 内距 ≈ 150px，留余量 |
| 左栏分隔 | `1px solid var(--background-modifier-border)` 仅**右侧**一条 | 与原生竖排 tab 同语言 |
| 导航项高 | **36px**（用户要求区间 36–40 的**下限**） | 6 项 × 36 = 216px，窄窗也不溢出 |
| 导航项内距 | `padding: 0 10px`，图标与文字 `gap: 8px` | — |
| 图标尺寸 | `1em`（跟随 `--font-ui-small`/导航字号，**不用绝对 px**） | 社区最佳实践：绝对 px 会基线错位 |
| 导航项圆角 | `var(--radius-s, 4px)` | ⚠️ `--nav-item-border-radius` **实测不存在**，不能引 |
| **选中态** | 底色 `--nav-item-background-selected` + 文字 `--nav-item-color-selected` + **左缘 3px 竖条** `--interactive-accent`（`border-left` 或伪元素） | 竖条是「当前位置」的强标记，纯底色在窄栏里对比不足 |
| **悬停态** | 底色 `--nav-item-background-hover`，文字 `--nav-item-color-hover`，**光标 `--cursor`** | ✅ 用户本轮明确要求「增加 Hover 背景色」；与原生 `.nav-file-title:hover` 同语言 |
| 选中 + 悬停 | 保持选中底色（`:hover:not(.is-active)` 才铺 hover 色） | 与项目既有口径一致（亮起按钮 `:hover` 加 `:not(.is-on)`） |
| 焦点态 | `box-shadow: 0 0 0 2px var(--interactive-accent-hover)` 或原生 outline | 键盘可达性 |
| 右栏 | `flex: 1 1 auto; min-width: 0; overflow-y: auto` | ⚠️ `min-width: 0` 必须给，否则长内容撑破分栏（本项目的老坑） |
| 右栏页标题 | 原生 `setHeading()` 迁到右栏顶部（**仍满足官方 guideline**） | 一页一个 heading，语义更正确 |

### 3.3 响应式降级（窄屏 / 手机）

| 视口 | 形态 |
|---|---|
| ≥ **720px** | 方案 A：左右分栏 |
| < **720px** | **方案 B 形态**：导航收成顶部一行**横向滚动 chip**（或原生 `<select>`），内容全宽；子分组回到可折叠 |

> 720px 沿用本项目既有窄屏阈值 `HEAD_NARROW_W = 720`（阅读器顶栏口径），全项目只保留**一个**窄屏阈值概念，减少心智负担。
> ⚠️ 触发降级判断用 `ResizeObserver`（`display()` 里量一次就失效），并在 `hide()` 里断开。

```
|  [i] 数据源管理                                                    v       |

|      +-- [i] 数据源凭据                                                    |

|      +-- [i] AI服务                                                        |

|  [i] 外观                                                          >       |

+---------------------------------------------------------------------------+
   顶层：加粗 + 图标 + 展开/折叠箭头（chevron-right 折叠 / chevron-down 展开）
   子项：向右缩进 + 图标 + 置灰小字
```

### 4.2 🔴 方案 B 的结构性风险（必须同时解决）

**Obsidian 原生设置页只有两层：标题 + 设置行。要加「手风琴」就必然变成三层**：

```
一级（可折叠） -> 子分组（可折叠） -> 设置行        <- ❌ 两层折叠嵌套，用户要连点两次
一级（可折叠） -> 设置行（子分组降级为组内小标签）   <- ✅ 只有两层折叠
```

> ⇒ **若选方案 B，必须同时决定「子分组降级为不可折叠的组内标签」**（否则「点开数据源管理 → 里面还有个要再点开的数据源凭据」，正是当前「层级模糊」的加强版）。
>
> 这也意味着方案 B **不是纯样式改造**：`createGroupSection` 的折叠能力要**只保留在一级**，子分组标题改为静态标签。这是 D-1 的一部分。

### 4.3 方案 B 的规格

| 项 | 规格 |
|---|---|
| 顶层行高 | **36px**，加粗（`font-weight: 600`，⚠️ 与 heading 一致但**不缩小**） |
| 顶层图标 | `1em`，颜色 `--text-muted`（展开时 `--text-normal`） |
| 箭头 | `chevron-right`（折叠）/ `chevron-down`（展开），色 `var(--nav-collapse-icon-color-collapsed)` / `--nav-collapse-icon-color`，`transition: transform .15s ease`（**写在基础规则上**，本项目 §10 老坑：写进作用域类会随摘类失效只剩单向动画） |
| 子项缩进 | **24px**（`padding-left: 24px`）+ 层级线 `--nav-indentation-guide-width` / `-color` |
| 子项字号 | `--font-ui-smaller`（置灰 `--text-muted`，字距 `0.02em`） |
| hover | 同 A：`--nav-item-background-hover` |

## 5. 视觉规范（Light / Dark 双主题一致）

### 5.1 🔴 零硬编码：亮/暗适配的实现方式

**不写任何一处的具体色值**，全部走语义变量 —— 这是唯一的适配方式（写死 `#fff` 会在暗色主题下白得刺眼，写死 `#333` 会在亮色下糊成一片）：

```css
/* 导航项：两句到底，亮/暗自动跟随 */
.rl-set-nav-item {
    color: var(--nav-item-color);                    /* 指向 --text-muted */
    cursor: var(--cursor);
}
.rl-set-nav-item:hover:not(.is-active) {
    color: var(--nav-item-color-hover);               /* 指向 --text-normal */
    background: var(--nav-item-background-hover);     /* 指向 --background-modifier-hover */
}
.rl-set-nav-item.is-active {
    color: var(--nav-item-color-selected);
    background: var(--nav-item-background-selected);
    box-shadow: inset 3px 0 0 var(--interactive-accent);   /* 左缘竖条，⛔ 不用 border-left（会撑宽） */
}
```

| 设计意图 | 变量 | 亮色主题实际值（默认主题） | 暗色主题实际值（默认主题） |
|---|---|---|---|
| 常态文字 | `--nav-item-color` → `--text-muted` | 中灰（≈ `#6b6b6b`） | 浅灰（≈ `#9a9a9a`） |
| 悬停文字 | `--nav-item-color-hover` → `--text-normal` | 近黑 | 近白 |
| 悬停底色 | `--nav-item-background-hover` → `--background-modifier-hover` | 极浅灰（≈ `#f0f0f0`） | 极浅白（≈ `#ffffff0d`） |
| 选中竖条 | `--interactive-accent` | 主题强调紫 | 主题强调紫（亮一档） |
| 分组标题 | `--text-faint` | 浅灰（≈ `#9a9a9a`） | 暗灰（≈ `#6b6b6b`） |
| 边框/分隔 | `--background-modifier-border` | `#e0e0e0` | `#333333` |

### 5.3 分组标题（回应用户 4 条要求之「大写 + 小字号 + 置灰 + 拉开间距」）

**🔴 必须分两层两个规格**，不能一套打天下：

| 层 | 规格 | 理由 |
|---|---|---|
| **一级**（在 A 方案里 = 左栏导航项；在 B 方案里 = 手风琴顶层） | **不缩小**（跟随 `--font-ui-medium`）、`font-weight: 600`、`--text-normal`、**带图标** | 它是「导航」不是「标签」。若把它也缩小置灰，就失去了「到哪里去」的引导力 |
| **子分组**（子项 / 组标签） | `--font-ui-smaller`、`font-weight: 500~600`、`--text-muted`、**字距 `0.02em`**、上间距 `--size-4-3`、下间距 `--size-4-2` | 这才是用户说的「小字号 + 置灰 + 拉开间距」。**它比它下面的设置行更弱**，层级才立得住 |

**关于「大写」**：
- 中文界面**没有大小写概念** ⇒ 等效手段 = **小字号 + 置灰 + 增大字距**（字距是中文里唯一的「标签感」来源）。
- 英文/未来多语言时可用 `text-transform: uppercase`，但 ⚠️ **与 Obsidian 官方 guideline 的 sentence case 冲突**（见 D-3）。
- ⛔ **不要用 `letter-spacing` 过大值**（> 0.06em）—— 中文会被拆得读不出来。

**拉开间距的具体值**（层级阶梯，回应用户「拉开间距」）：

```
一级导航项      行高 36px，项间 2px
  子分组标题    上间距 12px（--size-4-3）+ 下间距 8px（--size-4-2），行高 24px
    设置行      行高 40px（原生 setSettingItem 自适应），行间 0
```

### 5.4 行高与 hover（回应用户 4 条要求之「36–40px + hover 背景色」）

| 元素 | 行高 | 说明 |
|---|---|---|
| 一级导航项（A 左栏 / B 顶层） | **36px** | 取用户区间 36–40 的**下限**：6 项 × 36 = 216px，窄窗/手机降级时也不溢出 |
| 子分组标题 | 24px | 标签不宜撑高 |
| 设置行 | 沿用原生（约 40px） | ⛔ **不改原生 `.setting-item` 的行高** —— 官方 guideline 明确要求设置项保持原生外观，改高度会破坏跨插件一致性 |

**hover 背景色的适用范围**（重要，避免与此前裁定冲突）：

| 元素 | hover 行为 | 依据 |
|---|---|---|
| 设置页**导航项**（左右分栏的左栏 / 手风琴顶层） | ✅ **铺底色** | 用户本轮明确要求；且与原生 `.nav-file-title:hover` 同语言 |
| 设置页**子分组标题**（现有 `.rl-svc-group-title:hover`） | ✅ 铺底色（只铺「标题 + 箭头」这一小段 `width: fit-content`） | 既有实现，保持不变 |
| 阅读器**并排切换类**（字体/阅读/行宽/缩进/字重 + 主题色卡） | ⛔ **只变色不铺底** | 用户 2026-09-14 裁定（并排按钮铺底会连成色带）—— **本条不受影响** |

> 🔴 一句话记法：**「竖排的导航项」铺底，「横排的并排切换」只变色。** 二者不冲突。

### 5.5 空间利用率（回应用户「空间利用率低」）

| 手段 | 做法 |
|---|---|
| 右栏独占视口 | A 方案下右栏 `overflow-y: auto`，**只有右栏滚动**，左栏固定不动 |
| 一行内消化次要信息 | 「行名 + 说明 + 控件」三层压成**两层**（说明降为 `--font-ui-smaller` 的第二行），避免每行都撑成三行高 |
| 子分组默认展开 | A 方案下子分组内容**默认展开**（内容已短，折叠反而增加点击）；B 方案下由用户控制 |
| 移除重复标签 | 「关于」独立成页后，不再需要为它保留一级标题的分隔留白 |
