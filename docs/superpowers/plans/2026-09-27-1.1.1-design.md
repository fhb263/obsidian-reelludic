## 1. 版本边界（D-1 的核心）

用户说「规划 1.1.1 版本」并给了 5 条。按项目自身版本策略，这 5 条的重量极不均衡：

| 项 | 性质 | 预估批次量 |
|---|------|-----------|
| ①②③ | 修复 / 体验 | 小（各 1 批） |
| ④ | 全新能力面（内置音频播放器 + 视图注册 + 自适应 + lrc 渲染） | 中～大（3 批） |
| ⑤ | 全新能力面 ×2（Legado 规则引擎 / Z-Library 反爬 / 四平台音乐下载） | 大（4～6 批） |

**两条路线：**

- **路线甲（推荐）— 「1.1.1 收敛，能力批另开」**
  - `1.1.1` = ① + ② + ③（三个修复/体验，一版打磨）
  - `1.2.0` = ④ + ⑤（两个全新能力面，符合同一版本策略）
  - 理由：④⑤ 单是「设计与金标准核实」就已是独立工作量；塞进 patch 号会把 1.1.1 拖成季更版，且发布粒度变糊（一个 patch 含三种性质）。
- **路线乙 — 「1.1.1 全装」**
  - `1.1.1` = ① ② ③ ④ ⑤ 一次性（延续 1.1.0 的「合并式大版本」习惯）
  - 代价：周期长、回归面大；⑤ 的平台侧接口随时失效，会拖住 ①②③④ 的发布。

- **(b) 推荐 —— 去 callout 外壳，保留标题与封面**：`> [!bookinfo]+ **《X》**` → `**《X》**`（或直接不写标题，靠 frontmatter `title`），`> ![[…]]` → `![[…]]`。

**书籍 · Z-Library**

| 事实 | 说明 |
|------|------|
| **无官方公开 API** | 所有开源客户端都是逆向：登录 `rpc.php`（email/password）→ 搜索 → `/eapi/book/{id}/{hash}/file` 取下载直链 |
| **域名轮换** | `z-library.se` / `singlelogin.re` / `go-to-zlibrary.se` 不定期失效，需外部源发现 |
| **风控** | 免费账号下载配额（约 10 本/天）、登录风控、偶尔验证码 |
| 参照 | Python 生态的 `zlibrary` 客户端（PyPI）；同类还有 Telegram bot 形态客户端 |

### 6.3 方案对比

**⑤-a 网文下载（Legado 书源）**

| 方案 | 内容 | 优点 | 缺点 |
|------|------|------|------|
| **A（推荐）规则引擎子集** | `pure/legadoRule.ts`：CSS 选择器 + `@text/@href/@html/@ownText` + `##正则##替换##` + `||` 备选 + `{{key}}/{{page}}` 模板 + `@JSon:` JSONPath；**`@js:` 一律标记「不支持」并跳过该源** | 零依赖、纯函数、全可单测、无任意代码执行面 | 覆盖率受限（含 JS 的源不可用） |
| B 全引擎（含 JS 沙箱） | 用 `new Function` + 自建宿主层（`legado.http.*`/`java.base64`/`java.aes`/`java.md5`…） | 覆盖社区源多数 | 工作量与安全面都最大；`java.*` 语义映射是无底洞；书源可执行任意代码 |
| C 降级（只支持 JSON/RSS 型） | 只吃返回 JSON 的源 | 最省 | 价值低，多数书源是 HTML 型 |

**⑤-b Z-Library**

| 方案 | 内容 | 优点 | 缺点 |
|------|------|------|------|
| **A（推荐）用户给定链接 → 落盘** | 设置里填可用域名 + 粘贴会话 Cookie；用户把书页 URL 贴进弹窗 → 插件解析下载直链 → 落盘 + 自动关联 `bookFile` | 不碰登录/风控/验证码；面最小；域名失效用户自己换 | 需用户手动找书页 |
| B 内置账号登录 + 搜索 | 邮箱/密码登 `rpc.php`，站内搜索 | 体验完整 | 域名轮换 + 风控 + 可能验证码 + 配额；维护成本高 |
| C 不做 | 只保留既有「关联本地文件」 | 零风险 | 不满足需求 |

**⑤-c 音乐下载**

| 方案 | 内容 | 优点 | 缺点 |
|------|------|------|------|
| **A（推荐）单平台起步** | 从 LyricFlux 裁剪出**网易云免费通道**（搜索 + `outer/url` 试听 + 歌词 + 封面 + 内嵌标签），不涉加密与 Cookie | 代码量小、合规风险低、可先跑通链路 | 曲库覆盖单平台 |
| B 全量四平台 | 搬 `downloadManager` 全量（含 QQ/酷狗/酷我 + Cookie + VIP） | 覆盖最好 | 许可证风险（D-13）+ 平台接口失效维护 |
| C 外部工具桥接 | 检测并调用用户自装的 `music-dl`/`go-music-dl` CLI，结果回填条目 | 合规风险最低、实现最省 | 用户需自装工具；跨平台路径探测脆弱 |
