日期：2026-09-20

## 0. 需求拆解

| 编号 | 需求原文要点 | 类型 |
|---|---|---|
| R1 | 侧栏列表中「顶部标题 / 左侧彩色指示条 / 正文文本 / 右侧操作区」没有统一网格对齐 | 纯 UI（样式） |
| R2 | 书签边栏「清除全部」→ 改为**能看到具体条目并支持勾选单条或多条删除** | UI + 交互 + 逻辑 |
| R3 | 顶栏绝对居中导致长章节名挤压右侧图标 → 三问：右组不压缩 / 标题溢出方案 / 窄屏降级 + 16px 间距规范 | 纯 UI + 降级逻辑 |
| R4 | 目录侧栏字数统计：中文按「字」，英文按「单词」 | 纯逻辑 + 显示口径 |

四条互相独立，可分别实施与验收。

### 1.1 三阅读器同构

| 文件 | 顶栏 | 侧栏 |

三者共用同一套 CSS 类，**改动落在 `styles.css` + 少量 DOM 节点，不涉及三份逻辑分叉**。

### 1.2 侧栏现状坐标（相对侧栏左缘 X=0，右缘 W）

当前样式链：
- `.rl-reader-toc-pane` / `.rl-reader-toc-list`：`padding: 2px 6px 10px`
- `.rl-reader-ex-list`：`padding: 2px 0 10px`（**右侧 0，与上面 6 不一致**）
- 分区头 `.rl-reader-ex-hlcount`：`padding: 8px 8px 2px`
- 列表项（`.rl-reader-bm-item` / `.rl-reader-hl-item` / `.rl-reader-ex-item`）：`padding: 5px 8px 5px 16px`
- 类型指示条 `::before`：`left: 6px; width: 5px; height: 14px`（书签绿 / 高亮黄 / 摘抄蓝）
- 分区头按钮 `.rl-reader-hl-clearall`：`padding: 2px 8px` + `1px` 边框；`.rl-reader-hl-head { padding-right: 8px }`

⚠️ 侧栏是**两层容器叠加水平内边距**，务必按嵌套链算（首版曾漏算 `toc-list` 那一层）：

```
.rl-reader-toc                        （flex 列，无水平 padding）
├─ .rl-reader-toc-tabs                （底部页签行）
├─ .rl-reader-toc-pane                padding: 2px 6px 10px        ← 第 1 层
│   └─ .rl-reader-toc-list            padding: 2px 6px 10px        ← 第 2 层（仅目录页有）
│       └─ .rl-reader-toc-item        padding: 5px 8px
└─ .rl-reader-toc-pane .rl-reader-ex-pane   padding: 2px 6px 10px  ← 第 1 层
    ├─ .rl-reader-hl-head             padding-right: 8px
    │   └─ .rl-reader-ex-hlcount      padding: 8px 8px 2px
    ├─ .rl-reader-bm-list             （无 padding 规则）
    │   └─ .rl-reader-bm-item         padding: 5px 8px 5px 16px
    ├─ .rl-reader-hl-list             padding: 0 0 6px
    ├─ .rl-reader-ex-head             （仅 margin / border-top）
    └─ .rl-reader-ex-list             padding: 2px 0 10px
```

实测（推算值，可直接在测试库 DevTools 复核）：

| 元素 | 左缘 x | 右缘 |
|---|---|---|
| 侧栏 pane 内容盒 | 6 | W−6 |
| 分区头标题文字（如「书签（1）」） | **14**（6 + 8） | — |
| 彩色指示条 | **12**（6 + 6，宽 5 → 12–17） | — |
| 目录项文字（`.rl-reader-toc-label`） | **20**（6 + 6 + 8） | — |
| 目录项字数数字 | — | **W−20**（6 + 6 + 8） |
| 标注项正文（引用） | **22**（6 + 16） | — |
| 标注项定位文字 | — | W−14（6 + 8） |
| 分区头「清除全部」按钮**外框** | — | W−14（6 + 8） |
| 分区头「清除全部」按钮**文字** | — | **W−23**（再减 padding 8 + border 1） |

**结论：四条不同的左基线（12 / 14 / 20 / 22）同时存在**，右侧也有三条互不相同的边界（W−20 / W−14 / W−23）—— 这正是用户看到的「没有遵循统一网格」。目录页与标注页各自多套一层 padding，是偏差的主要来源。

### 1.3 顶栏现状与重叠阈值

```
.rl-reader-head        position:absolute; left/right:0; display:flex; gap:10px; padding:10px 16px
.rl-reader-title-wrap  position:absolute; left:50%; translateX(-50%); max-width:44%   ← 脱离 flex 流
.rl-reader-ops         margin-left:auto; flex-shrink:0
```

固定占用宽度估算（窗口宽 W）：

| 区段 | 内容 | 宽 |
|---|---|---|
| 左 | 侧栏开关 34 + gap 10 + 笔记 34 | ≈ 78 |
| 右 | 快捷入口 6 个图标 ≈ 214 + gap 6 + 设置 ≡ ≈ 30 | ≈ 250 |

标题块居中占 `[0.28W, 0.72W]`，右组占 `[W−266, W−16]`。

> **重叠判据：`0.72W > W − 266` → `W < 950px`。**
> 即窗口宽度小于约 950px 时，长章节名就会压到右侧图标上 —— 分区宽度 44% 不随右组真实宽度收缩，这是「绝对居中」的固有缺陷。

`flex-shrink: 0` 目前只加在 `.rl-reader-ops`，左组两个按钮未加（现无实际溢出，但同属该需求）。

### 1.4 字数统计现状

| 位置 | 函数 | 口径 |
|---|---|---|
| TXT 目录 | `pure/txtParse.txtChapterChars` | 段落 `[startPara[i], startPara[i+1])` 的**去空白字符数** |
| EPUB 目录 | `pure/epubParse.epubTocCharCounts` → `chapterTextLength` | HTML 剥标签后 `xhtmlToText(html).length`（**字符数**） |
| 展示 | `pure/readerToc.formatCharCount` | < 1 万原样；≥ 1 万「x.x万」 |

🔴 **关键约束**：`chapterTextLength` **同时被阅读进度加权使用**（`EpubReaderModal.chapterSizesCache` → `estimatePercent`）与 TOC 重建阈值（`epubParse` L260）。**它是进度口径，不能改**。本次只在「展示层」换口径：新增独立计数函数，`chapterTextLength` 原样保留。

`txtChapterChars` 目前唯一调用点是目录显示（L1558），可安全换口径。

## 2. 开源金标准参照

| 主题 | 金标准 | 对我们的结论 |
|---|---|---|
| 阅读器顶栏 | foliate-js `reader.html`：`#header-bar` 只放「侧栏开关 + 设置」，书名/章节名不进顶栏（在侧栏里）；Readium / Calibre 同思路 —— **头部只承载导航与工具，标题让位** | 支持「右组优先、标题可让位」的取舍方向 |
| 工具栏溢出 | PatternFly Toolbar：**> 2~3 个动作应收进 overflow menu（kebab）**，窄屏时连主按钮也回收到 overflow | 窄屏降级 = 收进「更多」是业界通行做法，不是妥协 |
| 多选删除 | Material 3 Selection：`checkbox` 是「可选多条」的唯一通用语义；进入选择模式后**工具栏替换为「已选 N + 操作」**；desktop 下 checkbox 可常显或 hover 显示；点击目标 ≥ 24×24 | R2 采用「选择模式 + 头部工具条替换」 |
| 批量删除确认 | Eleken bulk-actions：选择态必须有**可见的上下文操作 + 确认**，不要静默生效 | 删除所选走既有 `ConfirmModal` 二次确认 |
| 中英字数口径 | Unicode UAX#29 / `Intl.Segmenter`；CJK 惯例**按字**（各计数工具均如此），拉丁语系**按词** | CJK 逐字计 + 拉丁逐词计 = 统一的「阅读量单位」 |

## 3. R1 侧栏网格对齐规范

### 3.1 规范定义（8px 安全边距 + 16px 双文本线，4px 栅格）

```
│← 8 ─→│← 5 →│← 3 →│                    │← 8 →│
├──────┼─────┼──────┼────────────────────┼─────┤
  pane   指示条 间隙   文本区（左线 16）      右线 16
```

| 令牌 | 值 | 说明 |
|---|---|---|
| `--rl-side-pad` | 8px | 侧栏左右安全边距（pane padding） |
| `--rl-side-bar-x` | 8px | 指示条左缘（相对侧栏） |
| `--rl-side-bar-w` | 5px | 指示条宽（**保持不变**） |
| 文本左线 | 16px | 头标题 / 目录项文字 / 列表项文字**全部对齐到此** |
| 文本右线 | 16px | 列表项定位文字 / 目录项数字 / 头部按钮**外框**对齐到此 |

### 3.2 改动前 → 改动后

| 元素 | 前 | 后 |
|---|---|---|
| `.rl-reader-toc-pane` padding-left / right | 6 / 6 | **8 / 8** |
| `.rl-reader-toc-list` padding-left / right | 6 / 6（多余的第 2 层） | **0 / 0**（层次收干净） |
| 三类列表项 padding-left | 16 | **8** |
| 类型指示条 `::before` left | 6 | **0** |
| 分区头标题文字 x | 14 | **16**（8 + 8） |
| 目录项文字 x | 20 | **16**（8 + 0 + 8） |
| 标注项正文 x | 22 | **16**（8 + 0 + 8） |
| 指示条 x | 12 | **8**（8 + 0，占宽 5 → 8–13） |
| 目录项数字右缘 | W−20 | **W−16** |
| 标注项定位文字右缘 | W−14 | **W−16** |
| 分区头按钮外框右缘 | W−14 | **W−16** |

**收益**：四条要素归到两条垂直线（左 16 / 右 16），指示条独立占槽；所有间距都是 4px 栅格整数倍。

## 4. R2 书签「清除全部」→ 多选删除

### 4.1 现状

- 三区（书签 / 高亮 / 摘抄）头部结构完全相同：`计数 + [清除全部]`，`clearAll` 一次 confirm 后**全量删除**。
- 单条删除已有：**右键**条目（书签走 `removeBookmarkItem`，高亮走 `removeHighlight`）—— 但没有任何视觉提示，用户不知道能右键。
- 用户诉求：**能看见具体条目、可勾选单条或多条删除**。

### 4.2 三个方案

**方案 A（推荐）：头部按钮由「清除全部」改为「选择」，进入多选模式**

```
常态                                   选择模式
┌─────────────────────────────┐        ┌──────────────────────────────────┐
│ 书签（1）          [清除全部]│   →    │ ☑ 已选 1    全选  删除所选  取消 │
├─────────────────────────────┤        ├──────────────────────────────────┤
│ ███ 摘到的一句…  第3章·42%  │        │ ☑ ███ 摘到的一句…   第3章·42%   │
│ ███ 另一句…      第5章·12%  │        │ ☐ ███ 另一句…       第5章·12%   │
└─────────────────────────────┘        └──────────────────────────────────┘
  点击 = 跳转                            点击 = 勾选（不跳转）
  右键 = 删一条（隐藏技能）                删除所选 → ConfirmModal 确认一次
```

- 进入：点头部「选择」。
- 退出：点「取消」；或删完自动退出；点空白不退出（与阅读器既有「无主动关闭入口」口径一致）。
- 「全选」在模式内（Material 的 bulk selector 语义），**不做**「全不选」（避免与取消混淆）。
- checkbox：24×24 热区，`--rl-side-check` 自绘（复用 `.rl-mark-check` 的网格法，见 UI-GUIDE §7.4）；选中态用强调色底 + 勾。
- 选择模式下条目**不再响应右键删除**（避免与勾选语义打架）。

**方案 B：保留「清除全部」，另加「选择」按钮**
两个按钮并排。优点是不改变老用户肌肉记忆；缺点是危险按钮常驻、头部更挤（侧栏最窄 180px 放不下「选择 + 清除全部」两个中文按钮）。

**方案 C：不改头部，改为 hover 显示删除图标 + Ctrl/Shift 多选**
改动最小，但「能看到具体条目并勾选」的诉求没被满足，且 Ctrl/Shift 多选在侧栏列表里可发现性极差。

### 4.3 推荐

方案 A。理由：符合 Material 3 selection mode + PatternFly bulk selector 两条金标准；头部只有一组按钮、窄侧栏也放得下；把「清空」这个不可逆操作降级为「勾选后删除」，危险面同时收窄。

### 4.4 作用范围（待裁定，见 D-6）

| 选项 | 说明 |
|---|---|
| 仅书签区 | 用户本次只提书签；改动面最小 |
| 三区统一（书签 / 高亮 / 摘抄） | 三区头部与列表同构，统一后交互一致；工作量约 1.5 倍，且高亮/摘抄删除要走既有批量删除 + 笔记回写通道 |

## 5. R3 顶栏布局

### 5.1 方案 T-A（推荐）：流式三段 + 中段压缩

```
┌──────────────────────────────────────────────────────────────────────┐
│ [☰][▤]   ←16px→   第 12 章：一个很长很长很长的章节…   ←16px→  [🔖][✏]…[≡] │
└──────────────────────────────────────────────────────────────────────┘
   左组 flex-shrink:0        中段 flex:1 1 auto; min-width:0        右组 flex-shrink:0
```

- 中段（标题容器）`flex: 1 1 auto; min-width: 0; padding: 0 16px;`，标题在其中**居中**（`justify-content:center`）。
- 右组 `flex-shrink: 0`（现状已有）+ 左组补 `flex-shrink: 0`。
- 溢出时**只有标题被压缩**，右侧图标热区与视觉 100% 完整 —— 直接满足需求 1。
- 代价：标题中心不再等于视口中心（等于「左右按钮组之间的中点」）。宽窗口下两者差 ≤ 数 px；窄窗口下标题居中语义本就失去意义。

### 5.2 中间标题两种溢出表现（需求 2，二选一或叠加）

**表现 ① 省略号 + 悬停全称**

```
空间足够                       空间不足                      悬停
┌──────────────────────┐      ┌──────────────────────┐     ┌──────────────────────┐
│  第 12 章：一个很长… │      │  第 12 章：一个很长… │     │  ┌────────────────┐  │
└──────────────────────┘      └──────────────────────┘     │  │第 12 章：一个很长很│  │
   text-overflow:ellipsis        … 后接省略号，右对齐        │  │长很长的章节标题   │  │
   + data-tip 全称（项目既有       文字边缘干净             │  └────────────────┘  │
   globalTooltip 通道，零新增）                             └──────────────────────┘
```

- 实现：`text-overflow: ellipsis` + 既有 `data-tip` 机制（零新增依赖，Obsidian 悬停即显示全称）。
- 优点：零成本、语义最强、窄屏可读性最好（能看出被截断）。
- 缺点：视觉上有「硬切」感。

**表现 ② 左右渐变遮罩（fade out）**

```
┌────────────────────────────────────────┐
│ ░░第 12 章：一个很长很长很长的章节░░   │   ← 两端 16px 渐隐，无省略号
└────────────────────────────────────────┘
  mask-image: linear-gradient(90deg, transparent 0, #000 16px,
              #000 calc(100% - 16px), transparent 100%)
```

- 优点：观感柔和，像「被界面吞掉」，适合沉浸式阅读器。
- 缺点：**被吞掉的内容看不出被截断**（用户可能以为书名就长这样）；`mask-image` 与 `text-align:center` 叠加后两端淡出不对称（文字越长越明显）。
- 建议：**①为主**；若要 ②，用 ①+② 组合（省略号 + 只做**右侧**单侧淡出），避免双侧淡出的不对称问题。

### 5.3 极端窄屏降级（需求 3）

按 PatternFly 的 overflow 口径，把**快捷入口 6 个图标**整体收进「更多」⋮ 菜单：

```
宽（≥ 900px）                          窄（< 900px）
┌────────────────────────────┐         ┌──────────────────────┐
│ [☰][▤]  第12章…   🔖✏❝文🌐✨ ≡ │  →     │ [☰][▤]  第12章…    ⋮ ≡ │
└────────────────────────────┘         └──────────────────────┘
                                          ⋮ 点开 = 竖向图标列表（复用 .rl-reader-menu 浮层）
```

- 保留在栏上：侧栏开关、打开笔记、标题、**更多 ⋮**、设置 ≡。
- 收进「更多」：书签 / 高亮 / 摘抄 / 翻译 / 网络搜索 / AI 搜索（6 项，与 ≡ 菜单同款浮层，选中态沿用 `.rl-quick-active`）。
- 触发方式（待裁定 D-3）：纯 CSS 断点（`@media` / `@container`）或 `ResizeObserver` 按**实测所需宽度**动态加类。后者更准（不依赖猜阈值），但要多一个 observer；前者零 JS。

### 5.4 间距规范（需求 4）

| 项 | 值 | 依据 |
|---|---|---|
| 标题左安全距离 | **≥ 16px** | 用户指定 |
| 标题右安全距离 | **≥ 16px** | 用户指定（对称） |
| 顶栏自身内边距 | 16px（现状已达标） | `padding: 10px 16px` |
| 按钮组内间隔 | 左组/右组内 6px、快捷入口 2px（现状） | 不动 |
| 左组 ↔ 中段、中段 ↔ 右组的**最小**间距 | **≥ 16px** | 由中段 `padding: 0 16px` 保证 |

> 即：`左组 ← 16px → 标题 ← 16px → 右组`，三段互不侵入。

## 6. R4 字数口径（中文按字 / 英文按词）

### 6.1 口径定义

统一的「阅读量单位」= **CJK 字符数 + 拉丁单词数**：

| 文本 | 计数 | 结果 |
|---|---|---|
| `你好世界` | 4 个 CJK 字 | 4 |
| `Hello world` | 2 个词 | 2 |
| `第 1 章 hello 世界` | 字：第/章/世/界 = 4；词：1、hello = 2 | 6 |
| `Don't over-think` | 2 个词（撇号属词内，连字符断开 — UAX#29 口径） | 2 |

实现基准（金标准）：

1. CJK 逐字：`/\p{Script=Han}|\p{Script=Hiragana}|\p{Script=Katakana}|\p{Script=Hangul}/gu`（日韩同属「按字」惯例）。
2. 拉丁逐词：优先 `Intl.Segmenter(locale, { granularity: 'word' })` 取 `isWordLike`（UAX#29 真源）；环境不支持时回退 `[\p{L}\p{N}]+(?:['’\-][\p{L}\p{N}]+)*`。
   - ⚠️ 不为大文档把 segmenter 迭代器 `[...spread]` 成数组（每段都持有 input 引用，10 万词会吃几百 MB，见 `supun.io/js-words`）。逐段落调用并只累加计数。

## 9. 风险与红线

| 风险 | 处置 |
|---|---|
| 改动 `chapterTextLength` 会**同时改变阅读进度百分比** | 本次不动该函数；只新增展示口径函数（M5 明确隔离） |
| 顶栏由 absolute 改 flex，可能影响「沉浸模式 `translateY` 隐藏」与 `::after` 渐变线 | 两者都基于 `.rl-reader-head` 自身，与定位方式无关；改后需真机验证沉浸切换 |
| 侧栏 padding 变化会让已记住的侧栏宽度（180–480px）观感略变 | 宽度是用户可拖的值，不受影响 |
| M4 删除走既有批量删除通道（含笔记「## 高亮 / ## 摘抄」回写） | **复用** `onPurgeAnnotations` / `removeHighlight` / `removeBookmarkItem`，⛔ 不新写删除逻辑，避免笔记镜像区失同步 |
| 新增 `Intl.Segmenter` 依赖 | Electron/Chrome 87+ 原生支持；仍写正则回退路径并单测两条分支 |
