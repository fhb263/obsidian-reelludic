# 1.0.3 UI 双主题实施计划（原生 / 现代）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 ReelLudic 增加「原生 / 现代」双界面主题，在设置页「外观」区提供切换；现代主题提供更圆润的卡片、分段式页签（纯文字 + 滑动描边药丸指示器）与更明确的层级阴影，且默认「原生」时观感与 1.0.2 完全一致。

**Architecture:** 三层落地 —— ① `styles.css` 新增 `--rl-t-*` 令牌层（圆角/阴影/位移/时长/缓动），组件内所有硬编码圆角与阴影改为引用令牌；② 现代主题的令牌覆盖写在 `.rl-theme-modern` 选择器下，该作用域由插件在 `document.body` 上挂载（**一处挂载覆盖主界面与全部弹窗**，避免逐 Modal 改造继承链）；③ 页签因「必须增删 DOM 节点」（加滑动指示器、去图标），是唯一走组件内 `{#if}` 结构分支的地方。

**Tech Stack:** TypeScript + Svelte 4 + esbuild + Vitest；纯逻辑下沉 `src/pure/themeTokens.ts`（TDD 红→绿）。

**起点：** HEAD = `10ea1f2`（设计文档定稿）。

## 前置说明：两处与设计文档的偏差（实施时按本计划执行）

1. **主题挂载点从「逐 Modal 基类」改为「`document.body` 单点挂载」**
   设计文档 §3.3 原计划新建 `RlModal` 基类，让 16 个 Modal 统一继承。**实测核查后放弃该方案**，原因见 Task 0 的「为什么改」。改为 `document.body` 挂载后，`.rl-theme-modern` 成为全局后代选择器前缀，**主界面与全部弹窗自动覆盖**，且不影响任何 Modal 的继承链。

2. **`.rl-theme-modern` 只挂在 `body` 上时特异性为 (0,1,0)，打不过 Svelte scoped 的 (0,4,0)**
   这是 Task 0 存在的**唯一理由**。解法是把 Svelte 组件里的**硬编码值抽成 `var(--rl-t-*, 原值)`**（scoped 选择器里引用变量，特异性问题自然消失），而不是靠提高外层选择器特异性去硬碰。**这是本计划的最高优先级纪律：任何主题 B 效果若未生效，先查该处的值是否还是硬编码。**

```ts
// 界面主题（原生 / 现代）纯逻辑：合法性归一 + 页签指示器定位。
// 主题效果本身靠 CSS 变量层（--rl-t-*），本模块只管可测的算术与兜底。
import type { UiTheme } from 'data/types';

/** 主题 → body 类名。native 不挂类（默认观感与 1.0.2 一致） */
export const THEME_CLASS: Record<UiTheme, string> = {
    native: '',
    modern: 'rl-theme-modern',
};

const VALID: UiTheme[] = ['native', 'modern'];

/** 主题字段归一：旧数据/损坏数据一律回退 native（保证升级不炸） */
export function normalizeUiTheme(raw: unknown): UiTheme {
    return typeof raw === 'string' && (VALID as string[]).includes(raw) ? (raw as UiTheme) : 'native';
}

/**
 * 页签滑动指示器的 transform/width 串。
 * @param offsetLeft 选中按钮相对容器的 offsetLeft
 * @param width      选中按钮宽度
 * @param pad        容器内边距（指示器 inset 与之一致）
 * @param scrollLeft 容器横向滚动量（窄栏溢出时非 0）
 *
 * 注意：`offsetLeft` 已含 padding 起点，故要减去 pad 才与 `inset: pad` 的指示器对齐；
 * 钳到 0 是为了 padding 大于 offset 的极端缩放下不产生负位移。滚动量同理要减（指示器在滚动容器内）。
 */
export function indicatorTransform(offsetLeft: number, width: number, pad: number, scrollLeft = 0): string {
    const x = Math.max(0, Math.round(offsetLeft - pad - scrollLeft));
    return `translateX(${x}px);width:${Math.round(width)}px`;
}
```

## 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 令牌未被引用导致 modern 局部不生效 | **P1** | 判定口诀：**某处不生效 = 该处值仍是硬编码**。逐个用 `grep -c "border-radius: [0-9]"` 清零后构建核对；`assert-symbols.cjs` 加反向断言守住 |
| 组件内 `var()` 第二参数漏写 → 令牌缺失时变空白 | **P1** | **所有令牌引用必须带 fallback 原值**。构建后用脚本检查：每个 `var(--rl-t-` 的括号内都必须含 `,`。例外仅限「整块挂在 `.rl-tabs-modern` / `.rl-theme-modern` 下」的规则（native 下不匹配），但本计划也一律写了 fallback |
| 同一文件多处 Edit 互相覆盖 | **P1** | 用「精确串 + 匹配次数断言」脚本（Task 3 Step 1 模板）；四个组件文件**逐个串行**改，不并行 |

## 与设计文档的差异说明（交付时须告知用户）

设计文档 §3.3 提出的 `RlModal` 共享基类方案**已在计划阶段废弃**，改为 `document.body` 单点挂载。原因：

1. **收益不足**：16 个 Modal 中仅 4 个持有 `plugin` 引用，其中 3 个（阅读器/播放器）又属排除范围 —— 为挂一个类去改 16 个文件的继承链，成本远超收益。
2. **风险更低**：继承链改造触碰全部弹窗构造路径，属 P1 风险；`body` 挂载零侵入，且**天然覆盖未来新增的弹窗**（原方案宣传的优点得以保留）。
3. **已验证可行**：`body.theme-light` / `body.theme-dark` 是 Obsidian 既有机制，插件在其上挂自有类由 `.rl-hide-scroll` 先例证明无副作用。

页签仍保留组件内结构分支（`{#if uiTheme === 'modern'}`），因为它是**唯一必须增删 DOM 节点**的地方。
