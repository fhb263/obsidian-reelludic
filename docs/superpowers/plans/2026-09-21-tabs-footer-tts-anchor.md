## 0. 一句话结论

1. **① 的真根因不是「胶囊样式」，而是「溢出方向」**：现代主题的分段容器继承了 `.rl-tabs`（原生主题那条）的 `justify-content: center`，内容一溢出就把内容整体左移 `C = (内容宽 − 可用宽) / 2` ⇒ **首个页签被推出容器外且滚不回来** + **绝对定位的指示器不参与这个位移、与选中页签错开 C 像素（宽度却正确）**。修法**一行**：本块显式 `justify-content: flex-start`（容器居中仍由 `margin: 0 auto` 承担，观感零变化）。
2. **② 底栏改五段**：`[«] [‹]  章节名… ━━━ 已读 29%  [⛶] [👁] [⏱] [🔊]  [›] [»]`；三阅读器同构（PDF 两端各一枚），**样式零新增**，位置靠**新建顺序**表达。
3. **③ 点击正文段落 = 重设起读点**：未朗读只记锚点，**正在朗读才立刻从该段读起** + 高亮平滑跳转；**锚点是章内偏移 ⇒ 换章必须作废**。

## 1. ① 海报墙顶栏页签：从「一张截图」到「一条一行修法」

### 1.1 取证一：把截图量化（不靠肉眼）

用户给的截图只有 364×85，肉眼会得出「胶囊和另一个胶囊叠在一起」这类**错结论**（实际是**指示器 + 底层按钮文字**两层叠加）。做法：自己解码 PNG → 放大 6 倍 → 叠加每 5px 一条的像素网格（`_zoom_crop.cjs` / `_analyze_shot.cjs` / `_map_shot.cjs`），量出的关键数字：

| 量到的东西 | 值 | 含义 |
|---|---|---|
| 蓝框（指示器） | `x = 155..249`、`y = 29..68` | 宽 **95px**、高 **40px** |
| 「影视」按钮 | `x = 98..195` | 宽 **97px** |
| 按钮间距 | 97 / 98 px（阅读→影视→游戏） | 均匀 ⇒ 布局本身没问题 |
| 指示器相对选中按钮 | **+57px、宽度差 −2px** | 🔴 **宽度对、位置错** ⇒ 指向「位置基准」，⛔ 不是「宽度算错」 |
| 用户 UI 缩放 | ≈1.2× | 所有长度除以 1.17~1.2 后与无头复现逐条吻合 |

### 1.2 取证二：无头复现（新增探针）

`_probe_tabs.cjs` / `_probe_tabs2.cjs` —— **真实 `app.css`（从 `obsidian.asar` 抽）+ 真实插件 `styles.css` + 真实组件 CSS（直接读 `HomeView.svelte` 的 `<style>` 块，⛔ 不手抄）**，6 页签 DOM 照抄模板。结论：

| 场景 | 实测 |
|---|---|
| 面板 `344px`（现状 `center`） | `client=322 / scroll=415 / maxScroll=93`、**首项视觉左缘 `−77` 而容器内缘 `16`**、`完全可见=false`、**可负滚量 `0`** | 
| 同上，但改成 `flex-start` | 首项左缘 `16` = 容器内缘 ⇒ **完全可见**、`maxScroll=186` ⇒ **可以滚回第一个** |
| 面板 `500 → 420` 且**不重算**指示器 | `dx = +40`、`dw = 0` | 
| 同上但**重算** | `dx = 0` | 
| `flex-start` 下 344 / 420 / 260 三种面板 | `offsetLeft` 都是 `[5,88,171,254,337,420]`（**与面板宽度无关**）⇒ 拖分隔条也不会失准 |

> ⚠️ 探针细节：`getBoundingClientRect` 会包含**正在进行的 transition**，所以量之前必须先 `indEl.style.transition = 'none'`（本项目已在「量到动画中间帧」上吃过亏）。

### 1.3 落地与验证

- 改动：`src/views/components/HomeView.svelte` 的 `.rl-tabs.rl-tabs-modern` 块加 **`justify-content: flex-start;`** + 一段「为什么」注释（把上面两条症状写进去，防回潮）。
- 断言（`assert-symbols.cjs`，仓外）：从 `main.js` 里取出该规则块，要求**含 `justify-content:flex-start`** 且**不含 `justify-content:center`**。
- 突变 **M355-a**（改回 `center`）⇒ `[RED ok]`。

## 2. ② 阅读器底栏：五段式

### 2.1 改动前后

```
改前（四段，全挤在右侧）
┌───────────────────────────────────────────────────────────┐
│ 章节名… ━━━━━━━━━━━  [⛶][👁][⏱][🔊]  [«] [‹] 已读29% [›] [»] │
└───────────────────────────────────────────────────────────┘

改后（五段，两端各一组翻页钮）
┌───────────────────────────────────────────────────────────┐
│ [«][‹]  章节名… ━━━━━━━━━ 已读29%  [⛶][👁][⏱][🔊]  [›][»]   │
└───────────────────────────────────────────────────────────┘
   ↑左组         ↑中段：读到哪儿            ↑高频四钮    ↑右组
```

- **左右两组翻页钮**：左 = 上一章 `«` / 上一页 `‹`；右 = 下一页 `›` / 下一章 `»`。两端是鼠标最容易停的位置；中段整块留给「我现在读到哪儿」。
- **`已读 X%` 从中段的分页器里挪到进度条右边**紧挨着（读数不再和翻页钮混在一起）。
- **PDF** 无章节概念 ⇒ 两端各只剩一枚翻屏钮，中段 = 页码文案 + 进度条 + 已读%。

### 2.2 实现要点

| 项 | 做法 |
|---|---|
| 三处同构 | `TxtReaderModal` / `EpubReaderModal` / `PdfReaderModal` 的 `buildFooter` **逐字对齐**（含注释口径） |
| 类名 | 两组共用 `.rl-reader-fnav`（22px 定高、`gap: 2px`、`flex-shrink: 0` 等既有规则**一并复用**）+ `-l` / `-r` 只用于区分左右 |
| 摆放 | 🔴 **靠新建顺序表达，⛔ 不再 `footer.insertBefore(fops, nav)`**（旧隐式约束退场，反向守卫钉住） |
| 样式 | **零新增**（间距由 `.rl-reader-footer` 的 `gap: 10px` 与进度条 `flex: 1` 天然给出） |

### 2.3 断言写法（本轮的重要一课）

- 计数型：`rl-reader-fnav rl-reader-fnav-l` / `-r` 各 **3**；裸 `cls: "rl-reader-fnav"` 必须为 **0**（旧形态退场）；`navL.createEl("button"` / `navR.createEl("button"` 各 **5**（TXT/EPUB 各 2 + PDF 1）。
- 🔴 **顺序型**（必需）：把每个 `buildFooter() { … }` 块切出来，逐段比 `indexOf` —— `左组 < fch < fprog < fprog-fill < fpct < fops < 右组`。
  **实证**：突变 **M355-b**（把「页码」与进度条换序）时，**上面所有计数断言全绿**，只有顺序断言变红 ⇒ **数量型断言对「搬位置」完全无感**。

## 3. ③ 朗读起读点：从「视口首段」到「你点的那一段」

### 3.1 先把现状说清（避免修错东西）

起读点**早就不是「章节开头」**（#342 起即「当前段落」），但它取的是**视口内首个可见段落** ⇒ 点屏幕下半段，起读点仍落在视口顶部那一段；而「朗读中换起点」这条通道**根本不存在**。本轮补的正是这两条。

### 3.2 设计

| 层 | 内容 |
|---|---|
| 纯逻辑 `pure/tts.ts` | 新增 **`blockStartAt(blockLengths, index)`**：第 index 个正文块的起点偏移 = 前面各块文本长度之和。🔴 与 `Range` / `locateSpan` **同口径**（只数文本、不数标签与 `<br>`）⇒ **段间空白文本节点也要计入**（故调用方取 root 的**全部子节点**，⛔ 不是只取元素）。非法长度按 0 计，⛔ 绝不产出 NaN。 |
| 服务 `TtsService` | `clickOffset(node)`（被点节点 → 向上取到 root 直接子块 → 下标 → `blockStartAt`；不在正文内 / 命中 root 自身 → `null`）、`anchorAt(node)`、`resetAnchor()`；`restart(offset?, smooth?)` 支持按章内偏移**重排队列位置**；`scrollTo(el, smooth)`。 |
| 起读点 | `startOffset()` = **两个来源一个出口**：**点过的段落优先**，没点过才退回视口口径。 |
| 交互 | 未在朗读**只记锚点**；**正在朗读才立刻从该段读起**（`if (this.speaking) this.restart(off, true)`）；高亮**平滑跳转**（`smoothOnce` **就地消费** ⇒ 只对这一次生效，逐句推进仍瞬移 —— 每句都动画在快速朗读时会「追不上」）。 |
| 不算换起点 | ① 点链接；② 有文字选区（在选字/摘抄）；③ 点在正文空白（`clickOffset` 返回 `null`）。 |
| 生命周期 | 🔴 **锚点是章内偏移 ⇒ 换章必须 `resetAnchor()`**（两阅读器 `switchChapter` 里紧跟 `stop()`）。锚点只是界面态：不落库、不写阅读存档、不碰用户高亮。 |
| 接线 | TXT 挂在**正文字根 `textEl`**（⛔ 不是滚动容器，否则点正文外空白也换锚点）；EPUB 在既有 `onFrameClick` 里，且 **必须排在沉浸门之前**（旧实现首行就是 `if (!this.immersive) return`）。 |

### 3.3 断言与突变

断言：锚点优先级（`startOffset` 窗口内 `if (this.anchor !== null) return this.anchor;`）、`if (this.speaking) restart(off, true)`、`this.at = startIndexAt(this.queue, offset)`、`blockStartAt` 定义 1 + 服务里调用 1、`resetAnchor()` 调用 2、TXT 接线挂 `textEl`、EPUB 设锚点在沉浸门之前、`anchorAt(target)` 恰好 2 处。

突变 9 条全数被抓（含 M355-e 忽略锚点 / f 无条件重启 / g 不改队列位置 / h EPUB 顺序 / i 换章不作废）。
