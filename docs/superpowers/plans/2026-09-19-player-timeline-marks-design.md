# 播放器：视频内打点 / 标记（进度条上的笔记点）—— 设计

> 状态：**已实施**（2026-09-19；D-1~D-5 全部裁定 —— **D-3 用户选定「点圆点 = 跳视频（吸附该秒）+ 悬停卡片看内容（含「在笔记中打开」）」**；手写行也算标记。M1~M6 已完成并部署，验证见 §6.2）
> 触发：用户 2026-09-19 原话 —— 「**视频内打点/标记（视频 → 笔记）**：① 在进度条上显示小圆点。当用户在视频任意时间点写下笔记时，进度条对应位置自动生成一个标记。② 点击进度条上的标记，可以快速定位到该时间点对应的笔记内容。」
> 关联资产：`docs/superpowers/plans/2026-09-19-player-timestamp-capture-design.md`（#326~#332：时间戳插入 / 点击跳转 / 一键截图，本设计**直接复用**它产出的时间戳数据）

---

## 0. 需求拆解（两件事，可独立交付）

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| **R1** | 进度条上显示标记 | 视频笔记里已有的「时间戳点」**自动**出现在进度条对应位置，**不需要用户额外操作** |
| **R2** | 点击标记 → 定位到该时间点对应的笔记内容 | 点一下标记就能看到/到达「那一刻写的笔记」，而不是自己在笔记里翻 |

⚠️ **需要先对齐的一处用词**：「用户在视频任意时间点**写下笔记**」—— 按当前插件能力，这件事的**唯一入口**就是顶栏那两个按钮
（**T 插入时间戳** / **S 截图**），它们写进条目笔记的 `## 时间戳` / `## 截图` 两区。所以「标记」= **这两区里已有的时间戳行**，
不需要新的记录动作。（若你想要的是「在笔记里随手敲一行字也算一个点」，那需要**手写行也纳入解析**，见 D-1 Ⓐ 的括注。）

## 1. 生态金标准检索（流程①）

### 1.1 交互金标准 = **YouTube 章节**（官方帮助文档 + 主流指南逐条一致）

| YouTube 的做法 | 对应本需求 |
| --- | --- |
| 进度条上以**竖线**把条分成若干段 | R1（标记形态的可选案之一） |
| **悬停**在段落上 → 上方浮出**章节标题**（+ 缩略图） | R2 的「先看内容」 |
| **点击段内任意位置** → 直接跳到该段 | R2 的「走过去」 |
| 播放器左下角常显**当前章节名**（面包屑） | 可选的加分项 |
| 章节的**数据源就是描述里的纯文本列表**（`0:00 标题`，一行一条） | 🔴 **与本项目天然同构** —— 我们的 `## 时间戳` 区就是「一行一个时间戳」 |

### 1.2 另一条金标准 = **热度曲线**（YouTube「最常重播的部分」/ B 站「高能进度条」）

在**进度条上方**画一条曲线（高度 = 该时刻被回看的次数），**不占进度条本身**。本需求不含「次数」，但**这个位置**值得借鉴
（标记层要么压在条上、要么浮在条上方，是 D-2 的取舍点）。

### 1.3 生态内同类插件（Media Extended）**没有这个功能**

- 它有 ⭐（插入时间戳）/ 📷（截图）/ **媒体片段**（`#t=start,end`，可右键时间轴「创建片段」）/ **交互式字幕**（点字幕跳转）。
- 但公开文档里**没有「进度条上的标记」**这一项。
- 桌面播放器侧同样少见：**VLC 有「书签」但不画在进度条上**；mpv 靠第三方脚本画在 OSD 上。
⇒ **结论：这件事在生态里没有现成实现可抄；但交互惯例有明确金标准（YouTube 章节）。**

参考：YouTube 官方帮助 <https://support.google.com/youtube/answer/12825599>、章节格式指南 <https://chapter-generator.com/blog/how-to-use-youtube-chapters>、Media Extended 用户指南 <https://deepwiki.com/aidenlx/media-extended/4-user-guide>。

## 3. 方案（逐项选择题，附推荐）

### D-1 标记的数据源

| 方案 | 说明 | 评价 |
| --- | --- | --- |
| **Ⓐ 每次开播放器时解析条目笔记（推荐）** | 扫 `## 时间戳` / `## 截图` 两区，用 `parseTimeLink` 取秒数；插完/截完**即时重解析** | **零 schema 改动、零迁移、零漂移**（真源仍是笔记）；代价是每次读一次笔记（本地文件，可忽略） |
| Ⓑ 存进 `catalog.json`（`entry.videoMarks: []`） | 写入时顺带落库 | 读得快；但**真源变两处**（笔记 + 库），会漂；还要动 `normalizeEntry` 白名单 + 处理旧数据 |
| Ⓒ 两者都要 | 库为缓存、笔记为准 | 复杂度最高，收益不明显 |

### D-2 标记的**形态与位置**（象形）

```
Ⓐ 圆点压在进度条上（用户原话）           Ⓑ 竖线分段（YouTube 章节）
┌──────────────────────────────┐        ┌──────────────────────────────┐
│  ●      ●        ●      ●    │        │  │      │        │      │    │
│ ████████████░░░░░░░░░░░░░░░░ │        │ ████████████░░░░░░░░░░░░░░░░ │
└──────────────────────────────┘        └──────────────────────────────┘
 条的厚度只有 6/9/14px → 圆点必然       竖线更「不打扰」，但它表达的是
 「骑」在条上，会盖掉一小段进度           **区间**语义（章节）而我们的是
                                         **离散点** → 语义偏了

Ⓒ 浮在进度条上方（热度曲线位）           Ⓓ 条上圆点 + 条下刻度（折中）
┌──────────────────────────────┐        ┌──────────────────────────────┐
│    ●      ●        ●      ●  │        │   ●      ●        ●      ●   │
│ ████████████░░░░░░░░░░░░░░░░ │        │ ████████████░░░░░░░░░░░░░░░░ │
│                              │        │   ╷      ╷        ╷      ╷   │
└──────────────────────────────┘        └──────────────────────────────┘
 完全不占条的厚度（最不挡拖拽）          信息密度最高，但条的上下都动过、
                                        与既有悬停预览需要重新排

| 方案 | 评价 |
| --- | --- |
| **Ⓐ 圆点压在条上**（推荐，用户原话） | 最直观、实现最小；代价是**圆点会盖住它所在位置那一小段进度**，且拖拽到那一点手感略变 |
| Ⓑ 竖线分段 | YouTube 惯例，但它表达**区间**；我们的是**离散点** ⇒ 语义不符 |
| Ⓒ 圆点浮在条上方 | 完全不挡拖拽；但会**占用控制条上方空间**（那里现在什么也没有，倒是干净） |
| Ⓓ 上圆点 + 下刻度 | 信息最全、观感最重；改动面也最大 |

### D-3 **点击标记之后发生什么**（本需求最容易猜错的一处）

用户原话是「**点击**……快速**定位到该时间点对应的笔记内容**」。但播放器里「点标记」天然还有一层含义：**把视频跳到那一刻**。
四种组合：

| 方案 | 点击行为 | 悬停行为 | 评价 |
| --- | --- | --- | --- |
| **Ⓐ 只跳视频** | 视频跳到该时刻并播放 | 浮层显示「那一刻的笔记文字 / 截图缩略图」 | 最顺手（YouTube 同款：内容在悬停里看、位置在点击里跳）；但**没直接到达笔记** |
| **Ⓑ 跳视频 + 浮层给「在笔记中打开」** | 同上 + 浮层里一个「打开笔记」按钮 | 同上 | 两个需求都满足，但**多一次点击** |
| **Ⓒ 点击直接去笔记** | 打开（或复用）条目笔记并**滚到那一行**（视频**也**跳过去） | 同 Ⓐ | 最贴用户字面（「定位到笔记内容」）；代价是**视野会被切走**（除非笔记已开在分屏） |
| **Ⓓ 点击跳视频，`Alt`/右键 → 去笔记** | 默认跳视频；修饰键 → 去笔记 | 同 Ⓐ | 不牺牲主路径，但**修饰键不可发现** |

> 🔴 **设计方倾向**：**Ⓐ + Ⓑ 的合体** —— 点击＝跳视频（意料之中、零打断），悬停浮层里同时给出**内容摘要**与**「在笔记中打开」**。
> 理由：播放器是个**全屏标签页**，「点击标记把视野切到笔记」会打断观看节奏；而「那一刻写了什么」正是悬停最该回答的问题。
> **但这条必须你点头** —— 它决定 R2 是「走过去」还是「先看一眼」。

### D-4 标记的范围（多集 / 多条目）

| 方案 | 说明 |
| --- | --- |
| **Ⓐ 只显示当前正在播的集（推荐）** | 进度条的时间轴只对应这一集；别的集的点画上去是**错的**（时间轴不同） |
| Ⓑ 全条目都画 | 会误导（第 3 集的 5:00 与第 1 集的 5:00 在同一位置）—— 仅当**单集视频**（`episodeFiles.length === 1`）时与 Ⓐ 等价 |

⚠️ **库内链接只有文件名、没有集号** ⇒ 需要 `videoPathTarget` 反查「这个文件是第几集」；反查不到的（文件被移出条目）**跳过不画**，不猜。

### D-5 点很多时的降级（防挤成一团）

| 方案 | 说明 |
| --- | --- |
| **Ⓐ 超过 N 个（如 12）时圆点缩小 / 半透明（推荐）** | 保持「有打点」的信息，不变成一条花边 |
| Ⓑ 相邻 < X% 的点合并成一个，悬停放列表 | 更干净，但要多一套合并与列表 UI |
| Ⓒ 不做降级 | 简单；用户自己点多了就承认观感变差 |

| **M7** | 验证链 | 受影响单测 → 产物断言（+新守卫）→ 断言级突变（≥4）→ 构建 → md5 三方一致 → 部署 → 镜像 → 文档 | 照既有流程 |

## 6. 决策结果（2026-09-19）

| 编号 | 结果 | 落地 |
| --- | --- | --- |
| **手写行算不算** | ✅ **算**（用户回「可以」） | `parseNoteMarks` 按**链接目标**解析、不看作者 ⇒ 天然涵盖（有单测钉住：旧文案形态同样能读） |
| **D-1 数据源** | ✅ Ⓐ 解析笔记 | 真源仍为笔记（零 schema 改动 / 零迁移 / 零漂移） |
| **D-2 标记形态** | ✅ Ⓐ 圆点压在进度条上 | 与用户原话「小圆点」一致；⚠️ **进度条 6/9/14px 三段高度不许改** |
| **D-3 点击行为** | ✅ **用户选定「跳视频 + 悬停看内容（含『在笔记中打开』）」** | 点圆点吸附到该秒；悬停卡片给内容 + 一个按钮（点了才开笔记并滚到该行） |
| **D-4 标记范围** | ✅ Ⓐ 只画当前集 | 库外深链按 `ep`、库内按文件名；**既无 ep 又无文件名的一律不画**（宁可不画也别画错位置） |
| **D-5 点多时** | ✅ Ⓐ 缩小变淡 | 纯样式（阈值常量），解析侧不动 |

### 6.2 已实施（M2~M6 · 2026-09-19）

- `EntryService.readNoteMarks(id)`（**笔记只经 EntryService**；无笔记 → 空数组）。
- `VideoPlayerView`：`.rl-vp-marks` 标记层（画在 `played`/`thumb` **之后**、`.rl-vp-tip` **之前** —— 否则已播区间的实心强调色底会把圆点吞掉；`pointer-events:none` ⇒ 命中判定走进度条自身的 pointer 事件、**不做逐点监听**、圆点不吃拖拽）、`pointerdown` 命中 → **吸附到该秒**、`updateTip` → **标记卡片**（`markCaption` + 缩略图 + 「在笔记中打开」）、`setMarks`、`loadedmetadata` / 切集后重画。
- `main`：`openEpisodeLocal` 改 `async`（先读标记再开播放器，3 处调用改 `void`）、卡片缩略图走 `getResourcePath`、`openNoteAtMark`（开/复用笔记并滚到该标记行）、`refreshPlayerMarks`（插入/截图后推给同条目正开着的播放器）。
