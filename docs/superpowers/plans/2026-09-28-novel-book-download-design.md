## 0. 出发点：能复用什么、真正的难点在哪

### 0.1 已经躺在仓里、几乎可以直接复用的基建（⑤-a 落地时建的）

| 能力 | 位置 | 对本方案的用处 |
|---|---|---|
| 落盘路径决策（净化文件名 / 重名去重 / 扩展名白名单 / 大小上限） | `pure/downloadPlan` | 书籍 `kind: 'book'` 已就位（`下载/书籍/`）；扩展名白名单已含 `epub/pdf/txt/mobi/azw3/fb2/cbz/zip` |
| 通用下载编排（下载 → 校验 → 落盘 → 去重） | `services/downloader.downloadToVault` | **直接复用**（它只认 `url + headers + kind + filename + validate`） |
| 写库内二进制（逐层补父目录 + `byteOffset/byteLength` 切片） | `main.writeBinaryFile` | **直接复用** |
| 字节防伪（64 KB 门槛 + 魔数嗅探，挡「302 到 HTML 错误页」） | `pure/downloader` | 复用 + 为 EPUB 补 `PK\x03\x04` 魔数 |
| 落盘后写回条目（`bookFile` / `audioPath`） | `EntryForm.applyDownloaded` → `EntryModal.update` | 复用同一条「下载成功 = 自动关联」通路（#402 建立） |
| 弹窗三段视图（搜索 / 结果 / 进度）+ 平台胶囊 + 试听四态 | `MusicDownloadModal` / `MusicDownload.svelte` | **同构照搬**成书籍下载弹窗（换掉「试听」那件） |

### 0.2 与音乐面的**结构性差异**（决定了方案不能照抄）

| 维度 | 音乐（已做） | 书籍 / 网文（本方案） |
|---|---|---|
| 取物方式 | 一次请求拿一个音频直链 | **搜索 → 详情 → 目录 → 逐章正文**（N 次请求，N 可能上千） |
| 产物 | 现成音频文件 | 常需**自行合成**（TXT / EPUB） |
| 单次体量 | 3–10 MB | 0.5–20 MB，但**章节数**是主要成本 |
| 源稳定性 | 大厂接口（网易云/QQ/酷狗/酷我） | 网文站**极易改版/反爬**；公版库稳定但书目有限 |
| 合规 | 平台 ToS（不绕 VIP） | **版权**是主要红线（网文站内容多为侵权转载） |

> 结论：**「公版/开放授权」与「网文站」必须分成两条通道**——前者可以默认开启、零维护；后者只能做「用户自备来源 + 明确后果」的可选能力。

## 1. 金标准检索结果（2026-09-28 实检）

### 1.1 网文侧（中文）

| 项目 / 规范 | 是什么 | 许可 | 对本仓的可用性 | 风险 |
|---|---|---|---|---|
| **legado（阅读）· JSON 书源** | 事实标准：一份 JSON 描述一个站的搜索/详情/目录/正文规则；取值语法混用 `@css:`、`@textNodes`、JSONPath（`$.data.books`）、正则替换（`##广告.*?广告##`、`##…##$1###`） | 客户端 GPL，**书源是数据不是代码** | 🔴 **生态最大**：社区书源成千上万、格式稳定多年 | 规则语法碎片化（同字段可能有 5 种写法）；不少源需 Cookie / 带 JS 混淆 |
| **legado Tauri · JS 书源** | 新一代：每个书源一个 `.js`，实现 `search / bookInfo / chapterList / chapterContent`；运行在 Boa JS 引擎，宿主提供 `legado.http`（异步） | 同上 | 表达力最强（可算签名、处理加密） | 🔴 要在本插件里**跑第三方脚本** ⇒ 安全与沙箱是硬门槛（见 D-18） |
| **社区书源仓库规范** | 公开仓 `repository.json` 索引 + 每源一个 `.js`（头 60 行解析 `@name/@version/@url/@tags`） | 同 | 可做「一键更新书源」 | 仓库内容不受我们控制 |
| **so-novel**（`freeok/so-novel`） | 交互式小说下载器：内置多书源 + 可自定义规则，导出 **EPUB / TXT / HTML**，支持批量 | 开源 | 作为**产品形态参照**（交互 = 搜索 → 选书 → 选格式 → 下载） | 书源 URL 会失效（其 README 自己提示「请用最新版」） |

### 1.2 文学侧（出版电子书）

| 来源 | 取物方式 | 授权 | 对本仓的可用性 |
|---|---|---|---|
| **维基文库 · WS Export** | `https://ws-export.wmcloud.org/?lang=zh&format=epub&page=<书名>` ⇒ **直接返回 EPUB**（也有 `-f txt`） | 公版 / CC BY-SA | 🔴 **中文古籍与公版文本最实用的免费合法源**，一次请求拿整本，零鉴权 |
| **Project Gutenberg · Gutendex API** | `https://gutendex.com/books?search=…&languages=zh` ⇒ JSON，`formats` 里给 EPUB/TXT 直链 | 公版 | 无鉴权、无 key；⚠️ **中文必须带 `languages=zh`**（不带时 CJK 检索恒 0 条，实测结论来自社区文档） |
| **Standard Ebooks** | 网页查询 → 下载 EPUB（高质量重制） | 公版（CC0） | 仅英文，但质量最好；无 API，需要 HTML 抓取 |
| **Anna's Archive** | 会员 JSON API `/dyn/api/fast_download.json`（**仅会员**）；免费路径是「慢速下载页」 | 混合（含侵权内容） | ⛔ 不适合作内置源：需凭据 + 法律风险 + 域名多变 |
| **Z-Library / LibGen** | 登录/凭据 + 日限额，域名常态化漂移 | 同上 | ⛔ 同上（只适合做「用户自备链接/凭据」的可选通道） |
| **Open Library / Internet Archive** | 元数据可查，正文多数是**借阅制**（受版权保护） | 混合 | 只能做**元数据**参考，不能直接下载正文 |

> **核实说明**：本节所有「可直接下 / 需鉴权 / 仅会员」都是查官方文档与官方 FAQ 得出的结论；⛔ 不把第三方脚本里的写法当成官方 API 契约（社区脚本常年失效）。

## 3. 方案对比（三选一或组合）

| | 甲 · 授权源直连（推荐先做） | 乙 · 网文源（legado JSON 书源子集） | 丙 · JS 书源（legado Tauri 格式） |
|---|---|---|---|
| 做什么 | 接 **维基文库 WS Export** + **Gutendex**（+可选 Standard Ebooks）；再加「粘贴直链」通道 | 实现**规则求值器子集**，支持导入 legado `.json` 书源：搜索 → 目录 → 逐章抓 → 合成 | 直接跑 `search/bookInfo/chapterList/chapterContent` 脚本 |
| 一次请求拿整本？ | ✅ 是（EPUB/TXT 直链） | ❌ 否（N 章，需并发/限速/续传） | ❌ 否（同乙） |
| 覆盖 | 公版古籍 / 英文公版；**新书与网文拿不到** | 🔴 中文网文主力 | 最贴近金标准生态 |
| 维护成本 | **近零**（官方接口，格式稳定） | 中（规则语法多；源易失效 → 只能靠用户自备） | 中高 |
| 技术风险 | 低（就是「下载一个文件」） | 中（HTML 解析 + 限速 + 合成） | 🔴 **高**：在 Electron 里跑第三方脚本 = 任意代码执行面 |
| 合规 | ✅ 公版/CC | ⚠️ 内容多为未授权转载 ⇒ 只能「用户自备来源」 | 同乙 |
| 估计体量 | 1 个弹窗 + 3 个纯模块（可比音乐那批更小） | 5–6 个模块 + 断点续传 | ＋沙箱与权限模型 |

**推荐**：**先甲后乙**（丙 明确后置）。理由：甲能以最小成本把「书籍下载」这条链路走通（并立刻验证「下载 → 合成/落盘 → 自动关联 → 笔记/阅读器可用」的全链路），乙 的价值高但成本与维护压力大，应当在甲把地基与 UI 范式固化之后再做。

## 4. 模块规划（拆到「可独立执行 / 可测」）

> 口径：**纯逻辑进 `pure/` 并配单测**；网络与落盘编排进 `services/`；宿主（vault / 写库）留在 `main.ts`；UI 与音乐面同构。

### 4.1 P0 —— 甲 方案（授权源直连）

| 模块 | 类型 | 职责 | 单测点 |
|---|---|---|---|
| `pure/bookSourceMeta` | 纯 | 三个授权源的**元数据归一**（标题/作者/语言/格式/字节数/直链），以及 `formats` 里挑最优格式（EPUB > TXT） | 缺字段、非 EPUB/TXT、多格式排序 |
| `pure/downloadPlan`（扩展） | 纯 | `book` 白名单已够；补 **EPUB 魔数**（`PK\x03\x04`）与 `html/toobig` 判定 | 魔数表、错误页识别 |
| `services/bookDownload` | 服务 | 编排：`searchAuthorized(source, keyword)` → 结果列表；`downloadBook(url, {kind:'book'})` → 复用 `downloadToVault` | 注入假 http，验控制流 |
| `BookDownloadModal` + `BookDownload.svelte` | UI | 三段视图（照搬音乐那套） | 产物断言（懒渲染/胶囊/按钮/文案） |
| 入口 | UI | 书籍表单「本地文件」旁的 📚 + 右键菜单 + 命令面板 | 断言「与音乐面同款 `.rl-ai-btn`」 |

### 4.2 P1 —— 乙 方案（网文源）

| 模块 | 类型 | 职责 | 单测点 |
|---|---|---|---|
| `pure/legadoSource` | 纯 | 解析/校验 legado `.json` 书源：必需字段、`bookSourceType===0`（文本）、**危险规则识别**（`webView` / 登录项 / JS 段） | 缺字段、类型不符、含 `webView` |
| `pure/ruleExpr` | 纯 | **取值规则求值器子集**：把规则串编译成步骤序列（`@css:` / `@textNodes` / `@json:` / `@attr:` / `##正则##$1###` / 字符串处理链），对**已解析出的字符串/节点文本**求值 | 各语法分支 + 混用 + 非法规则回空 |
| `pure/chapterPlan` | 纯 | 目录 → 章节任务列表；限速与重试策略；断点续传的状态机（`pending/done/failed`） | 顺序、去重、失败重试上限 |
| `pure/novelText` | 纯 | 正文净化（去广告行、去站点水印、段落规整）+ 章节标题编号 | 广告正则、空行折叠 |
| `pure/epubPack` | 纯 | **TXT/章节 → EPUB**：极简 zip（`mimetype` **必须是第一条且 stored**） + `container.xml` + `content.opf` + `nav.xhtml` + 章节 xhtml；封面可选 | zip 结构、mimetype 序与压缩方式、CRC32 |
| `services/novelDownload` | 服务 | 编排：搜索 → 目录 → 并发抓章（默认 1 并发 + 间隔）→ 合成 → 落盘 → 写回 | 假 http 全链路 |
| `pure/downloadTasks`（可选） | 纯 + 字段 | 断点续传落库（append-only 新字段） | 序列化/反序列化、恢复 |

### 4.3 P2 —— 体验与运维

- **书源更新**：从用户指定 URL 拉 `repository.json`（只做**用户主动触发**，⛔ 不内置任何内容源地址）。
- **批量下载**：只允许「同一本书的分卷/分集」，⛔ 不做「一次下十本」。
- **目录回填**：EPUB 章节名可写回条目笔记的 `## 目录`（与既有 `toc` 字段同源）。

### 9.2 🔴 源码级对比：`go-novel` 反证出我们上批的 **4 处差距**

`zsyo/go-novel` 是 so-novel **规则格式的兼容移植**，所以它的 `internal/core/extract.go` / `search.go`
**就是对我们那套书源字段的第二份实现** —— 拿它逐条对，能查出我们漏了什么（这是本批最有价值的产出）。

| # | 差距 | 参考实现怎么做 | 我们的现状 | 严重度 |
|---|---|---|---|---|
| **G1** | **搜索直接跳详情页** | `result` 选择器**匹配 0 个**且 `book.bookName` 能命中时 ⇒ 判定「站点直接跳到了详情页」，**用 `resp.Request.URL` 当书籍地址**，并从详情页取书名/作者/最新章节 | ✅ **#420 已补**（`detailJumpHit` + `nodeHttp.finalUrl`） | 🔴 **中高**（把「能用」说成「源失效」） |

**同时确认我们对的地方**（两份实现在同一处写法一致 ⇒ 我们不是猜的）：

- `%s` 占位：GET 用 URL 编码、POST 直接替换 —— 与我们的 `fillSearchUrl` / `fillSearchParams` 一致 ✔
- 非 2xx 一律当失败、单源失败不影响其它源、按源分组显示 —— 一致 ✔

### 9.3 🔴 一处归类错误（必须指出）

`jbiaojerry/ebook-treasure-chest` 被列在「**公版书与经典文学搜索**」里 —— 它自己的仓库描述写的是：
「该库涵盖了 **帆书 app（原樊登读书）、微信读书、京东读书、喜马拉雅** 等读书 app 的**大部分电子书**」。
⇒ 这是**商业平台付费内容的下载链接聚合**，**不是公版书**。它与 **D-24(a)**（不内置内容源、不绕付费）冲突，
**不进「公版书」这一路**（同类还有 `wenshuoge`，虽自称公版但无许可证 ⇒ 代码不可复用，只能当书目参考）。

### 9.4 可用的公版书路（若重开）

按「真公版 + 可编程 + 无需登录」筛，只有两条站得住：
- **Gutenberg**（`gutenberg.org` 的 API / `gutendex.com`）—— 已在 #416 实测：**中文 444 种**、除繁体标题外一切正常；#417 按用户要求删掉了。
- **文硕阁**（`wenshuoge.com`）—— 自称公共版权、无需注册；⚠️ 无 API 文档、无 license ⇒ 只能**抓网页**，且**能不能抓、抓多少**要另做实测。
