# 00-需求澄清 — ReelLudic

> 阶段 0 产出物 | 日期：2026-08-25 | 门禁：G1 ✅ 已通过

---

## 1. 背景与目标

ReelLudic 是 fhb263 的第二个 Obsidian 插件（第一个是 obsidian-lyricflux，v1.4.4，267 单测全绿）。目标是在 Obsidian 库中管理**影视、书籍、游戏**三类收藏，把「收藏」变成「可追踪、可批注、可双链的结构化笔记资产」。

参考了 Serpent（独立数字资产管理应用）的库管理 UX（封面墙、标签、过滤），但差异化在于：**不做一个独立应用，而是把资产库原生建在 Obsidian 的双链笔记生态里**。

最终形态三库一体，分三阶段交付：

| 阶段 | 内容 | 版本 |
|---|---|---|
| 1 | 影视库 MVP（书架/追更/抓取/评分/链接/笔记） | v0.0.1 |
| 2 | 书籍库（PDF/EPUB 阅读器、批注高亮、双链跳转） | v0.1+ |
| 3 | 游戏库（游玩记录、攻略双链模板） | v0.2+ |

## 2. 用户画像

- 现有 Obsidian 用户，习惯 Markdown + 双链管理一切
- 追剧/看电影有「想看清单」「追番表」需求，希望记录观看进度
- 有收藏管理诉求但不想再装一个独立 App（数据孤岛）
- 暂无存量藏品，从零开始建库（先搭功能，不追求海量数据性能）

## 3. MVP 范围（影视库，v0.0.1）

| # | 功能 | 验收要点 |
|---|---|---|
| 1 | 手动添加 | 表单录入标题/封面/导演/演员/年份/类型/简介 |
| 2 | 自动抓取 | TMDB 主源搜索回填，手动可覆盖；无 Key 降级手动 |
| 3 | 书架视图 | 海报墙/列表双形态；按类型/年份/状态/评分筛选排序 |
| 4 | 状态流转 | 想看/在看/已看/弃剧 四态切换 |
| 5 | 进度记录 | 剧集记「季·集」（含历史）；电影记观看日期 |
| 6 | 评分 | 1~5 星，参与排序筛选 |
| 7 | 观看链接 | 预设平台模板（B站/Netflix/豆瓣/爱奇艺/腾讯视频）+ 自定义 |
| 8 | 追更表 | 独立视图；连载中条目一键标记「已更新」，记录最新集数+日期 |
| 9 | 详情笔记 | 每条目自动生成 .md（frontmatter + 评语 + 链接） |
| 10 | 混合存储 | ReelLudic/ 目录：catalog.json + entries/*.md + covers/ |

## 4. 非目标（第一版不做）

- 书籍阅读器（pdf.js/epubjs、批注、双链跳转）→ 阶段 2
- 游戏库（游玩记录、攻略双链）→ 阶段 3
- 移动端适配（桌面优先）
- 自动检测更新（追更纯手动）
- 批量导入（无存量数据）
- 多端同步（交给 Obsidian 自身机制）
- 豆瓣自动抓取默认开启（反爬风险，做默认关闭开关）

## 5. 成功指标

- 从零添加一部影视到书架 < 1 分钟
- 重启后数据完整、进度不丢
- ReelLudic/ 目录可整体迁移
- 核心纯逻辑单测覆盖；百级条目无卡顿

## 6. G1 门禁结论（三轮拷问摘要）

| 决策点 | 结论 |
|---|---|
| MVP 顺序 | 影视库先行 → 书籍 → 游戏 |
| 平台 | 桌面优先，移动端后续 |
| 存储 | 混合：JSON 目录 + Markdown 笔记 |
| 元数据获取 | 手动 + 自动抓取（TMDB 主源、豆瓣兜底【待验证】） |
| 状态/进度 | 四态 + 季集粒度 + 观看日期 |
| 评分 | 1~5 星 |
| 追更 | 独立追更视图 + 纯手动标记 |
| 笔记 | 每条目自动生成详情笔记 |
| 技术栈 | Svelte 4 + esbuild + TS + Vitest |
| 测试环境 | 复用临时测试库，build.bat + sync_plugin.ps1 部署闭环 |
