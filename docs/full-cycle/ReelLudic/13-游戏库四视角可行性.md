# 13-游戏库四视角可行性 — 阶段 3 巡检

> 游戏库 G2 产出物 | 日期：2026-08-27 | 结论：**四视角全绿**，v0.2 是轻量收尾（打磨 + 快速时长），无高风险项

---

## 1. UX 视角 — ✅ 可行

| 项 | 评估 |
|---|---|
| 快速时长记录 | 卡片「＋30 分钟」= 一步操作（类似书籍「＋1 集」/影视「已更新」心智），无学习成本 |
| 时长展示 | 「已玩 Xh / Nm」随进度条同级展示，信息层次清晰 |
| 打磨闭环 | 书籍库两轮 UI 修复（片长/导演按类型、文案软化、布局对齐）经验直接复用——game 类型做同款审查 |
| 风险 | 「＋30 分钟」按钮与状态徽章/编辑按钮布局需实测（卡片拥挤度），原型阶段确认 |

## 2. 开发视角 — ✅ 可行

| 项 | 评估 |
|---|---|
| 快速时长 | EntryService 新增 `addPlaytime(id, minutes=30)`（仅 game，分钟 ≥0 校验）→ 卡片按钮 + 右键菜单调用，纯逻辑可单测 |
| 打磨项 | 按书籍库同款模式修正：字段条件渲染 / 文案 / 时长格式（纯逻辑 `formatPlaytime` 可测） |
| 数据一致性 | playtimeMinutes 已存 catalog（事实源）+ frontmatter；`addPlaytime` 走 update 链路自动同步 |
| 复用 | 卡片按钮/右键菜单链路完全复用书籍库摘抄入口模式（MediaList prop → HomeView → plugin） |
| 风险 | 无新依赖；改动面小（EntryService 1 方法 + MediaList 卡片 + 打磨修正） |

## 3. 价值生态视角 — ✅ 可行

- v0.0.1 已验证 game 类型基础可用；v0.2 收尾后「影视/书籍/游戏」三库完整闭环
- 差异化不变：三库一体 + 双链原生；游戏库保持轻量（不堆功能，防面面俱到）
- 竞品（Game Library 类插件）多为列表+模板，无三库一体；本阶段以完成度取胜

## 4. 技术趋势视角 — ✅ 可行

- 无新依赖、无生态赌注（Steam/RAWG 均后置）
- 卡片按钮/右键链路沿用已验证模式（Svelte on: 事件 + DOM API），无新技术引入
- 数据格式（playtimeMinutes 数字字段）明文自控，可长期演进（未来若做 playSessions 日志，schema 只增字段）
