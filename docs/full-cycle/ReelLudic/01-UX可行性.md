# 01-UX可行性 — 用户体验视角巡检

> G2 产出物（视角 1/4）| 日期：2026-08-25 | 结论：**可行**，移动端标「待验证」

---

## 1. 信息架构

```
ReelLudic（三入口：Ribbon 图标 + 命令 + 侧边栏）
├── 书架视图（主界面）
│   ├── 工具栏：视图切换（海报墙/列表）｜筛选（类型/年份/状态/评分）｜排序｜+ 添加
│   └── 内容区：封面卡片网格 或 表格列表
├── 追更视图
│   └── 连载中条目卡片：封面 + 当前集数 + 「已更新」按钮 + 更新日志
└── 条目详情（点击卡片）
    ├── 弹窗内嵌详情（快速查看/状态切换/评分）
    └── 打开 .md 详情笔记（深度编辑/写评语/加链接）
```

设计原则：**卡片墙快速浏览 → 点击进详情笔记**，符合 Obsidian「所见即笔记」的心智；追更视图独立，避免连载条目淹没在书架的「已看」堆里。

## 2. 状态流转交互

```
想看 ──▶ 在看 ──▶ 已看
  │       │        │
  └───────┴──▶ 弃剧 ◀┘    （任意态可直转弃剧）
```

- 卡片上状态徽章可点击，弹出四态快捷菜单（1 步切换）
- 剧集在看时显示进度徽章「S4E16」，点击可快速 +1 集
- 状态切换写入 catalog.json + 同步更新 frontmatter（保持双向一致）

## 3. 追更表交互

- 卡片主操作：**「已更新」按钮** → 弹小框确认最新集数（默认 = 当前+1）→ 写入进度 + 生成更新日志 + 时间戳
- 视图内按「最近更新时间」倒序，刚更完的置顶
- 空态引导：无连载中条目时显示引导文案 + 跳转书架按钮

## 4. Serpent 借鉴与取舍

| Serpent 的 UX | 借鉴 | 取舍 |
|---|---|---|
| 封面墙浏览 | ✅ 海报墙网格 | 不做瀑布流吸顶筛选（Obsidian 视图宽度受限） |
| 标签/打分 | ✅ 1~5 星 + tags | 评分收敛到 5 星制（Serpent 是连续打分） |
| 合集（collection） | ❌ 阶段 1 不做 | 用 tags 代替，合集功能留待有需要 |
| 插件/脚本/MCP | ❌ 完全不做 | Obsidian 生态本身有 API，无需自造 |
| WebDAV 云同步 | ❌ 不做 | 交给 Obsidian 同步插件 |

## 5. 视图尺寸适配

- Obsidian 视图（workspace leaf）宽度不固定：海报墙用 CSS grid + `auto-fill, minmax(140px, 1fr)` 自适应
- 列表视图列数可配置（避免窄视图挤压）
- 封面加载：本地优先 + 懒加载 `loading="lazy"`（百级条目无卡顿）

## 6. 待验证项

| 项 | 状态 | 说明 |
|---|---|---|
| 移动端适配 | **待验证** | 桌面优先策略，移动端布局（触控快捷菜单、窄屏网格）留待移动端阶段实测 |
| 大量条目性能（500+） | 待验证 | 当前无存量数据；虚拟滚动/分页留待实际规模出现后评估 |
| 海报墙观感 | 待 G3 原型确认 | 线框+高保真原型给用户确认视觉方向 |

## 7. 结论

UX 层面**可行**：交互模式成熟（卡片墙+筛选+状态切换是内容管理类应用的标配），与 Obsidian 视图体系兼容。主要不确定性在移动端（已排除在 v0.0.1 外）和大规模性能（当前无数据压力）。
