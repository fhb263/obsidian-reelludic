> 书籍库 G2 产出物（视角 4/4）| 日期：2026-08-26 | 结论：**可行**，无生态赌注，block reference 机制长期稳定

---

## 1. Obsidian 机制趋势

| 趋势 | 对书籍库的影响 | 评估 |
|---|---|---|
| block reference（`^id`）为官方核心机制 | 摘抄引用的地基，跨版本稳定 | ✅ 低风险（Obsidian 1.x 起长期维护） |
| 自定义命令/视图 API 成熟 | 摘抄命令 + 挂载弹窗无阻力 | ✅ 低风险 |
| 移动端同步普及 | 桌面优先策略不变；摘抄工作流在移动端可用（粘贴 + 编辑笔记） | ✅ 无风险 |
| 官方对 PDF/阅读能力演进 | 阅读器后置可等生态成熟再评估 | ✅ 不阻塞 |

## 2. 阅读器后置的合理性（技术视角）

- pdf.js 高亮**无法持久化写回 PDF**（渲染层 overlay 方案，无开源成功先例）
- epubjs CFI 锚点可行但工程量大，且移动端渲染吃力（04 文档已提示）
- Obsidian 自身及社区对文档阅读的投入在演进——**等待成熟方案比自造更优**；v0.1 的摘抄（外部复制）不依赖任何渲染生态

**判断**：阅读器后置不是回避，而是技术时机选择——在渲染方案成熟前，先把「摘抄 + 双链」这个 Obsidian 原生强项做深。

## 3. 外部阅读器复制通道趋势

| 通道 | 现状 | 评估 |
|---|---|---|
| Zotero | 桌面阅读 + 复制习惯成熟 | ✅ 主通道 |
| 微信读书/Kindle | 划线→复制文本已是高频操作 | ✅ 主通道 |
| 纸质书 | 手动录入页码/文本 | ✅ 可选 |
| 浏览器网页阅读 | 复制标准 | ✅ 兼容 |

复制粘贴是跨平台、零依赖、长期稳定的输入方式；未来若出现「剪贴板监控自动入库」，可在命令层增量实现，不影响既有架构。

## 4. 长期维护风险

| 风险 | 说明 | 对策 |
|---|---|---|
| Obsidian API 破坏性升级 | 历史上少见破坏性变更 | 沿用 minAppVersion 策略 |
| Svelte 4 → 5 | 保持 4，等生态稳定 | 与 v0.0.1 一致，不新增变量 |
| 数据格式锁定 | JSON + MD 明文自控 | 无锁定风险；摘抄即 Markdown 块 |
| block id 冲突（跨笔记） | Obsidian 块 id 全局唯一约定 | generateBlockId 用时间戳+随机后缀（纯函数单测） |

## 5. 结论

技术趋势视角**可行**：block reference 是 Obsidian 官方长期维护的核心机制，摘抄功能建立其上无生态赌注；外部复制粘贴通道跨平台长期稳定；阅读器后置是技术时机选择而非妥协。整体技术路线可持续 2~3 年无需重大重构。
