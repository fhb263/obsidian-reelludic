# 03-价值生态可行性 — 价值与生态视角巡检

> G2 产出物（视角 3/4）| 日期：2026-08-25 | 结论：**可行**，差异化清晰，但需明确定位

---

## 1. 同类 Obsidian 插件对比

| 插件 | 管理对象 | 形态 | 与 ReelLudic 的差异 |
|---|---|---|---|
| 各类「电影/观影清单」插件（如 Media DB、Movie Notes 类） | 影视 | 列表/表格 + 模板笔记 | 多为单库、无追更表、无自动抓取回填；ReelLudic 三库一体 |
| 书籍管理类（如 Books 插件） | 书籍 | 库 + 元数据 | 多为书摘/笔记管理，无阅读器、无影视/游戏 |
| 游戏库类（如 Game Library 插件） | 游戏 | 库 + 模板 | 生态相对小众，功能单薄 |
| obsidian-lyricflux（自家） | 歌词/音乐 | 渲染器 + 侧边栏 | 领域不同，但沉淀了构建/部署/测试约定可复用 |

**观察**：Obsidian 生态里「影视/书籍/游戏」各自有零散插件，但**三库一体 + 统一 schema + 双链原生**的完整方案尚未出现，存在生态位空白。

## 2. Serpent 竞品分析

| 维度 | Serpent | ReelLudic |
|---|---|---|
| 形态 | 独立桌面应用（Electron + SQLite） | Obsidian 插件（JSON + MD） |
| 对象 | 数字资产（图片/视频/3D，面向设计师） | 收藏内容（影视/书籍/游戏） |
| 笔记 | 无笔记体系 | 双链 + Markdown 原生 |
| 同步 | WebDAV 内置 | 交给 Obsidian 同步 |
| 迁移成本 | 应用内数据 | 目录级可移植，用户完全可控 |

**结论**：Serpent 解决「设计师的海量素材管理」，ReelLudic 解决「个人收藏的笔记化」，用户群和场景不重叠，反而互相启发 UX。

## 3. 差异化价值主张

1. **收藏即笔记**：每个条目是一个可编辑、可双链、可版本管理的 Markdown 文件——这是独立 App 做不到的
2. **三库一体**：一套 schema、一个心智模型、三种内容类型（预留 book/game）
3. **数据主权**：catalog.json + MD 明文存储，无锁定风险，Obsidian 同步免费可用
4. **渐进交付**：影视 → 书籍 → 游戏，每阶段独立可用，不是画饼

## 4. 生态位判断与风险

| 项 | 判断 |
|---|---|
| 需求真实性 | 高——Obsidian 用户普遍有收藏管理诉求，社区帖子高频 |
| 竞争强度 | 中——单库插件多，三库一体少；先发 + 质量可建立优势 |
| 分发渠道 | Obsidian 社区插件市场（BRAT/官方 registry），成本低 |
| 风险 | 功能面广（三库）可能稀释完成度 → 以「影视库先做深做精」对冲 |

## 5. 结论

价值生态视角**可行**：三库一体 + 双链原生在 Obsidian 生态内是差异化空白；与 Serpent 不构成竞争、互为启发。建议以「影视库做深」策略切入，避免面面俱到导致平庸。
