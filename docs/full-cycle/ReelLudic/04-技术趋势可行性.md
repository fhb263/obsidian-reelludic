# 04-技术趋势可行性 — 技术趋势视角巡检

> G2 产出物（视角 4/4）| 日期：2026-08-25 | 结论：**可行**，技术选型处于成熟稳定期

---

## 1. Obsidian 生态趋势

| 趋势 | 对 ReelLudic 的影响 | 评估 |
|---|---|---|
| 插件 API 持续演进 | 自定义 ItemView / SettingTab / 命令机制稳定成熟 | ✅ 低风险 |
| 自定义视图成为标配 | 复杂插件（如 Kanban、Dataview 类）已验证视图体系 | ✅ 低风险 |
| 移动端同步普及 | 桌面优先策略不受影响；移动端是后续增量 | ✅ 无风险 |
| 官方对 CSS 主题化支持 | 海报墙视觉需适配明暗主题 CSS 变量 | 🟡 注意用 var(--...) 而非硬编码 |

## 2. 移动端趋势（桌面优先决策依据）

- Obsidian 移动端性能与渲染能力弱于桌面，pdf.js/epubjs 在移动端尤其吃力
- 当前阶段桌面优先 + 视图容器用响应式 CSS（`auto-fill, minmax`），为移动端预留结构
- 移动端适配明确排期到后续阶段（书籍库阅读器阶段一并评估）

## 3. TMDB 服务稳定性

- TMDB API v3 自 2011 年运营至今，接口稳定、文档完善
- 免费 Key + 速率限制模式成熟，社区插件集成案例多（如各种影视插件）
- 风险点：无 Key 用户无法用自动抓取 → 已设计降级（手动录入不阻塞）

## 4. 书籍/游戏库技术储备（阶段 2/3 铺垫）

| 储备项 | 现状 | 评估 |
|---|---|---|
| pdf.js | 成熟（Mozilla 维护，Obsidian 社区已有集成） | ✅ 阶段 2 可用 |
| epubjs | 成熟（epub 渲染行业标准） | ✅ 阶段 2 可用 |
| 批注锚点方案 | 基于页码/文本选择定位，社区有参考实现 | 🟡 阶段 2 需专项设计 |
| 游戏元数据源 | RAWG API（游戏版 TMDB，需 Key） | ✅ 阶段 3 可用 |

## 5. 长期维护风险

| 风险 | 说明 | 对策 |
|---|---|---|
| Obsidian API 破坏性升级 | 历史上少见破坏性变更 | 跟随 minAppVersion 策略，锁定测试版本 |
| Svelte 4 → 5 迁移 | Svelte 5 已发布但 4 仍被广泛使用 | 保持 4，等生态稳定再评估升级 |
| 数据格式锁定 | JSON + MD 明文，格式自控 | 无锁定风险，schema 只增不改 |

## 6. 结论

技术趋势视角**可行**：所选技术栈（Obsidian API + Svelte 4 + esbuild + Vitest）全部处于成熟稳定期；数据格式明文自控无锁定风险；阶段 2/3 的技术储备（pdf.js/epubjs/RAWG）在生态中均有成熟先例。整体技术路线可持续 2~3 年无需重大重构。
