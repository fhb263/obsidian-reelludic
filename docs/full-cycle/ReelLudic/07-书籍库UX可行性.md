# 07-书籍库UX可行性 — 用户体验视角巡检

> 书籍库 G2 产出物（视角 1/4）| 日期：2026-08-26 | 结论：**可行**，摘抄工作流贴合 Obsidian 心智

---

## 1. 信息架构

```
书籍库（复用现有 7 Tab 统一视图）
├── 书籍页签（书架）
│   ├── 书籍卡片：封面 + 进度条(.rl-readbar) + 摘抄数徽标
│   └── 筛选排序（复用现有能力）
├── 书目详情笔记（核心）
│   ├── frontmatter（元数据 + 进度）
│   ├── 基本信息（callout + 属性表）
│   ├── 个人评语
│   ├── ## 摘抄（新增章节：块列表，每块 = 引用文本 + 页码 + 心得 + ^id）
│   └── 相关链接
└── 命令：添加摘抄（粘贴 + 页码 + 挂载书目）
```

设计原则：**书目笔记是书摘的聚合地，block ref 让摘抄可以被整个库引用**。摘抄区位于「个人评语」之后，语义上「先想法、后证据」，且位置固定便于合并写入（见 08）。

## 2. 摘抄交互流

```
外部阅读器选中 → 复制 → Obsidian 命令「添加摘抄」
  → 粘贴引用文本（自动清格式）→ 手填页码（可选）
  → 选择挂载书目（搜索或当前书籍）
  → 生成摘抄块：> 引用 + 页码 + 心得输入 + 自动 ^id
  → 追加到书目笔记「摘抄」区 → 可立即 [[书目#^id]] 引用
```

- 主操作 4 步内完成；页码可留空（未知页码场景不阻塞）
- 摘抄块模板：`> 引用文本` + `页码：p.xx` + `心得：` + `^id`
- 心得输入直接内联在生成弹窗（一次完成，不二次编辑）

## 3. 阅读进度交互

- 书籍卡片/编辑弹窗内：页码输入 + 百分比输入**双轨并存**（任一填写，另一自动换算）
- 状态 chips：想读/在读/已读/弃读（复用四态 + labels 文案）
- 进度条 .rl-readbar：page/totalPage 实时渲染，读完（page=totalPage）可提示一键置为已读

## 4. Readwise 借鉴与取舍

| Readwise 的 UX | 借鉴 | 取舍 |
|---|---|---|
| 摘抄自动同步 | ❌ 手动复制粘贴（无自动通道，换取零依赖） | 命令粘贴 30 秒内完成 |
| 高亮原文+评论结构 | ✅ 引用块 + 心得双栏 | 用 Markdown 引用块表达 |
| 标签/主题组织 | ✅ 心得区可写双链 | 不建独立标签体系，交给 Obsidian 原生 tags |
| 导出/回顾 | ❌ v0.1 不做 | 有需求再评估 |
| 订阅付费 | ❌ | 本地免费 |

**判断**：Readwise 解决「自动收集」，ReelLudic 解决「收集进 Obsidian 且可双链」——手动粘贴是成本换主权/可引用性，对 Obsidian 用户可接受。

## 5. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 粘贴格式杂乱（网页复制带样式） | 中 | 命令粘贴时清格式（取纯文本），模板统一引用块 |
| 页码手填易错/漏填 | 低 | 页码可选；提供「%」替代；显示于摘抄块供日后修正 |
| 摘抄区被用户重排/删除 | 中 | 章节位置约定 + 合并写入按标记行提取；用户明确移动时接受「引用可能断」的 Obsidian 通用行为 |
| 大量摘抄导致笔记过长 | 低 | 摘抄块只存引用文本（不存全文）；后续可评估折叠/子笔记 |

## 6. 待验证项

| 项 | 说明 |
|---|---|
| 命令粘贴体验 | 需原型（Phase 3）确认：弹窗布局/挂载书目选择方式 |
| 双轨换算 | 页码↔百分比换算是否自动联动，原型确认主次 |

## 7. 结论

UX 视角**可行**：摘抄工作流（复制→命令→粘贴→^id）是 Obsidian 用户已习惯的操作模式，书目笔记聚合 + block ref 引用符合「所见即笔记」心智；与 Readwise 对比，手动粘贴换来的本地数据主权与可引用性对目标用户是净收益。主要不确定性（弹窗布局/换算联动）将在原型阶段确认。
