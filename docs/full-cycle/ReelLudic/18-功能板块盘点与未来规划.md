## 0. 一句话结论

插件在**「管理 + 消费 + AI」**三条主线上已经相当完整（六类收藏、11 个元数据源、内置阅读器与播放器、追更 / 排期 / 统计三块看板、五套 AI 用途）；**真正的结构性缺口在「生态联动」**——数据虽全部以 Markdown + JSON 落盘，但对 **Bases / Dataview 没有一等公民支持**，而这是「收藏库能不能被别的插件查询、能不能长在 Obsidian 原生生态里」的关键；其次是**移动端**（`isDesktopOnly: false` 却只有浏览能力）与**数据运维的深度**（回收站只覆盖条目，没有库级快照与版本历史）。

## 3. 真正值得做的五件事（按价值 / 成本排序）

> 排序依据：**用户价值 × 与现有架构的贴合度 ÷ 实现风险**。前两项是「生态联动」欠账，后三项是把已有能力做深。

### A. Bases 一等公民支持（最高价值，中等成本）

**为什么**：用户明确要「`catalog.json` 的字段映射为 Bases 可识别的属性视图，让用户直接用 Bases 查询收藏库；阅读进度 json 也可被 Bases 识别」。这是把插件从「一个能管收藏的插件」变成「收藏数据长在 Obsidian 生态里」的分水岭，同时复用已有的 `pure/metaFields.ts`（字段真源）与 `pure/tableColumns.ts`（列池）。

**Bases 的能力边界（必须诚实说明）**：
- `.base` 文件只能查询**库内文件**的属性，属性来源 = **笔记的 properties / frontmatter**，或 `file.*` 元数据；它**不能**直接读 `ReelLudic/catalog.json` 里的 JSON 字段，也**不能**读 `阅读进度/*.json`。
- 因此「catalog → Bases」只有两条路：
  - **路线 A1（推荐）：把 catalog 字段补全进笔记 frontmatter**。已有基础：`entryFrontmatter` 已写出 id / type / title / status / rating / tags / created / updated / banner / year / genres / director / cast / progress_* / reading_* / page_count / read_minutes / playtime_minutes / progress_percent …；缺的是 `links`、`related`、`series_index`（已写）、`latestKnownEpisode`、`communityScore`、`sourceUrl` 等**运行态字段**。补全后 Bases 直接 `TABLE rating, year FROM "ReelLudic/笔记"` 即可用。
  - **路线 A2：插件生成 `.base` 视图模板**（一键在 `ReelLudic/视图/` 下写出若干 `.base`：六类各一份 + 阅读进度一份 + 追更一份），用户直接在 Bases 里打开即用。
  - **路线 A3（可不做）：阅读进度 JSON 进 Bases** —— 需要把每本书的进度**镜像到笔记 frontmatter**（`reading_page` / `reading_total_page` / `progress_percent` 已在写，但只在 `writeNote` 时刷新，阅读器改进度后不立即写）。⇒ 折中方案：阅读器**关闭时**（已有 `flushReaderStore` 钩子）刷一次笔记 frontmatter，让 Bases 的精度停留在「本次阅读结束」。

**落地清单**
1. `pure/baseView.ts`（新）：给定条目集合 + 字段清单 → 生成 `.base` YAML（列 / 排序 / 过滤 / 分组），纯函数可单测。
2. 设置页 › 高级设置 加一行「**生成 Bases 视图**」：一键写 `ReelLudic/视图/{电影,剧集,动画,书籍,游戏,音乐,追更,阅读进度}.base`。
3. 补全 `entryFrontmatter` 的运行态字段（append-only，逐个过 `normalizeEntry` 白名单 + `metaFields` 登记）。

### B. 移动端能力对齐（高价值，高成本）

**为什么**：`isDesktopOnly: false` 意味着用户会在手机上装它，但现在装完只能看列表。移动端的**阅读**（TXT / EPUB / PDF）其实不需要 Node——走 WebView 的 `fetch` / `FileReader` 就能读；真正做不了的是本地路径访问与 yt-dlp。

**落地清单**
1. 探测 `Platform.isMobile`，把「本地文件关联 / 播放 / 漫画压缩包 / yt-dlp」入口隐藏或降级（现在是**点了才失败**）。
2. 移动端 EPU​B / TXT / PDF 阅读器走纯 Web 实现（PDF 已有 pdfjs-dist，EPUB 已有 `pure/epubParse.ts`）。
3. 移动端「从系统文件选择器导入」→ 拷进库内再读（替代本地路径关联）。

### C. 数据体检与库级快照（中价值，中成本）

**为什么**：1.4.0 的清理能力已覆盖「孤儿封面 / 删除条目」，但**没有一个地方能一次回答「我的库健康吗」**。这类功能用户一旦用惯就是刚需。

**落地清单**
1. `pure/libraryAudit.ts`（新）：三方对账 —— ① catalog 条目 → 笔记是否存在 / frontmatter 是否与 catalog 一致（复用 `noteFingerprint`）；② 笔记 → 是否有孤儿笔记（catalog 里已无此 id）；③ 附件 → 是否有未被任何条目引用的文件（复用 `orphanAssets`）。
2. 设置页 › 封面与清理 加一行「**库体检**」：出一份分组清单，每组可勾选清理。
3. 库级快照：把 `catalog.json` + 全部笔记 + 附件清单打成一个 zip 存 `备份/`（复用 jszip，已有依赖）。

### D. 自定义视图预设（中价值，中成本，与 A 天然互补）

**为什么**：现在「筛选 + 排序 + 列」是一次性的，切走就没了。做成命名预设后，等于插件内的「Bases」。

**落地清单**
1. `settings.viewPresets?: ViewPreset[]`（append-only）：`{name, viewMode, filters, sort, columns, groupBy}`。
2. `MediaList.svelte` 顶部视图切换旁加「预设」下拉：保存当前视图 / 应用预设 / 删除。
3. 与 A 打通：预设可「导出为 .base 文件」。

### E. 时间序列与会话统计（中价值，低成本，纯读取现有数据）

**为什么**：`activityLog`（500 条）、`playSessions`、`readMinutes`、`watchedDate`、`createdAt` 都已经在落盘，**没有一处把它们当时间序列画出来**。统计页缺「趋势」这一层。

**落地清单**
1. `pure/trends.ts`（新）：按月 / 周聚合（新增条目数 / 完成数 / 阅读分钟 / 游玩分钟 / 平均评分），纯函数可单测。
2. 统计页加「趋势」卡片（折线 / 柱状，SVG 手绘不引依赖）。
3. 影视 / 音乐补 `watchSessions`（与 `playSessions` 同构）—— 这一步动 schema，需单独立项。
