## 阶段 1：追更/排期增强（v0.5 主功能）

### 现状摸底（实际数据）

- 追更表（TrackingBoard.svelte）：网站更新检测已具备——抓 `links[0]` 观看链接 HTML → `extractMaxEpisodeFromHTML` 正则提最大集数 → 对比已看集数；**10min 缓存**（updateCheckCache）；更新置顶 + 活跃度（active/idle/stale）排序；进入视图自动检测（`runChecks`，**Promise.all 全并发抓取**）+ 「重新检测」按钮（force）。
- 检测结果**仅存组件内存**（updateMap），退出视图即丢 → 每次进追更表全部重新抓取，对反爬站点不友好。
- 排期表（CalendarBoard.svelte）：月历 + 拖拽排期 + 过去日期禁用 + 清除排期；**与状态流转脱节**——排期到了无提醒、无操作入口。

### A2 检测结果落库

## 阶段 2：技术债与稳健性

### E 搜索缓存失效策略 ✅

- **现状**：`searchCache`（TTL 30min / maxSize 200）、`updateCheckCache`（TTL 10min / maxSize 100），内存 Map；**豆瓣 Cookie / TMDB Key / Bangumi Token 变更后旧结果继续命中**。
- **方案**：设置页保存任一凭据变更时调 `searchCache.clear()` + `updateCheckCache.clear()`（main.ts 设置保存回调统一入口 `invalidateCaches()`）。
- **测试**：searchCache.test 已有 clear 用例；新增集成验证（凭据变更 → 缓存清空 → 下次搜索直连源）。
- **复杂度**：低。

### G 双写冲突提示 ✅

- **现状**：catalog.json 为唯一事实源，笔记为展示层；用户直接编辑笔记后，任何写笔记操作（保存条目/摘抄/游玩记录）会**静默覆盖**用户改动（打开表单回填仅缓解「用户改了要落库」场景）。
- **方案**：写笔记前读取现有笔记，与「上次插件生成内容」比对（条目标 `noteFingerprint`，内容 hash）；不一致 → 确认提示「笔记已被外部修改：覆盖 / 保留」；「保留」分支走 noteGenerator 合并写入路径（策略 C 已实现，摘抄/游玩记录等依赖重写合并的操作不丢数据）。
- **复杂度**：中。

### H 清理与旧字段 ✅

- **孤儿封面清理工具**：扫描 `封面/`，找出未被任何条目 poster 引用的文件 → **列出清单**（不自动删，安全优先）→ 用户逐项确认删除（复用 vaultIO.deleteFile）。覆盖测试库 2 张 74B GIF 遗留场景。
- **localizePosters 弃用字段评估**：字段保留（schema 红线先例），评估是否移除设置页 UI 入口。
- **旧源 source 标签映射**：维持现状不清理（老条目展示不迁移，已确认）。
