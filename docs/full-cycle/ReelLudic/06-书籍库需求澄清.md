# 06-书籍库需求澄清 — ReelLudic 阶段 2

> 阶段 2 产出物（需求澄清）| 日期：2026-08-26 | 门禁：书籍库 G1（待确认）
> 前置：影视库 v0.0.1 已发布（G5/G6 通过后启动本阶段）

---

## 1. 背景与目标

影视库 MVP（v0.0.1）已验证「收藏即笔记」的可行性：catalog.json 管目录、Markdown 管笔记、双链就绪。阶段 2 把书籍纳入同一心智模型，并新增**书摘**能力——这是「收藏」走向「资产」的关键一步：书不只是被收藏，还能被摘录、被引用、被长期批注。

**范围锚点（经两轮 grilling 收敛）**：书摘双链 + 阅读进度先行；内置阅读器**后置**（独立版本评估），书籍追更**不做**。

## 2. 用户画像

- 现有 Obsidian 用户，习惯 Markdown + 双链管理一切
- **读书人**：纸质书 + 电子书混读，希望记录页码/百分比进度、摘抄金句、写心得
- 阅读场景分布：Zotero / 微信读书 / Kindle / 纸质书（摘抄从外部复制而来）
- 影视库用户自然延伸：同一批藏品统一管理，不新增学习成本

## 3. MVP 范围（书籍库 v0.1）

| # | 功能 | 说明 | 验收要点 |
|---|---|---|---|
| 1 | 摘抄录入 | 外部阅读器复制文本 → Obsidian 命令 → 粘贴 + 手填页码 → 生成摘抄块 | 从复制到生成摘抄 < 30 秒；无渲染依赖 |
| 2 | 摘抄存储 | 书目笔记内嵌「摘抄」章节；每摘抄一个 block id（`^id`） | 摘抄区与个人评语区并存，笔记可手动编辑 |
| 3 | 双链引用 | 摘抄块可被任意笔记 `[[书目#^id]]` 引用；阅读时跳回书目笔记 | 引用稳定、跳转生效 |
| 4 | 阅读进度 | 页码 + 百分比双轨记录；想读/在读/读完三态（复用四态 + 类型文案） | 进度与状态同步写入 catalog + frontmatter |
| 5 | 书籍卡片增强 | 书架书籍卡片显示阅读进度条（复用 .rl-readbar）+ 摘抄数徽标 | 百级条目无卡顿 |
| 6 | 书目字段增强 | Google Books 搜索补齐页数（pageCount 现成缺口）；ISBN/出版社等字段已就绪 | 搜索回填页数 |

## 4. 非目标（v0.1 不做）

- ❌ **内置阅读器**（PDF/EPUB 在 Obsidian 内阅读）→ 后置独立版本评估（pdf.js 高亮无法写回 PDF、体验天花板低）
- ❌ **文档内高亮批注**（渲染层 overlay）→ 依赖内置阅读器，一并后置
- ❌ **书籍追更**（漫画/连载小说「已更新」）→ 追更表保持影视向（isTrackingType 仅 tv/anime）
- ❌ **读书统计**（时长/日历热力图）→ 观察 v0.0.1 统计面板复用价值后再定
- ❌ **书摘导出/读书报告** → 有需求再评估
- ❌ **移动端适配** → 桌面优先不变

## 5. 成功指标

- **可用性**：从复制一段文字到生成可引用的摘抄 < 30 秒
- **可靠性**：摘抄 block id 不随笔记重排丢失；重启后数据完整
- **双链价值**：摘抄可被任意笔记 `[[#^id]]` 引用且跳转成功
- **一致性**：catalog（事实源）与 frontmatter 双向同步；进度/状态修改即时刷新

## 8. 待验证项（G2 阶段处理）

1. **noteGenerator 覆写风险**：笔记模板每次全量生成 → 若更新条目时重写笔记，摘抄区会被清空。需论证「只生成一次 / 合并写入 / 分文件」策略（见 08-开发可行性）
2. **block ref 兼容性**：Obsidian `^id` 块引用的稳定性、外部编辑（用户手改笔记）后 id 是否保留
3. **摘抄区位置约定**：摘抄区固定章节位置 + 文档约定，防止用户误删/重排破坏引用
