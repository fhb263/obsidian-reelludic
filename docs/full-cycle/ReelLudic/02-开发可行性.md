# 02-开发可行性 — 开发视角巡检

> G2 产出物（视角 2/4）| 日期：2026-08-25 | 结论：**可行**；豆瓣兜底标「待验证」，建议默认关闭

---

## 1. 技术栈评估

| 项 | 选型 | 依据 |
|---|---|---|
| 语言 | TypeScript（strict） | Obsidian 插件标准 |
| 构建 | esbuild + tsc | 沿用 lyricflux 已验证链（target es2018、cjs、external obsidian/electron/@codemirror*/@lezer*） |
| UI | Svelte 4 | lyricflux 已用 esbuild-svelte 链跑通；UI 密集场景开发效率高 |
| 测试 | Vitest | 沿用；environment node，纯逻辑可测 |
| 网络 | Node https / fetch | Obsidian 插件主进程可直接请求（fetch 受限时走 Node https，坑点见 lyricflux 经验） |

**结论：技术栈零新风险**，全部组件已在 obsidian-lyricflux 生产验证。

## 2. 模块可测性设计

纯逻辑模块（无 obsidian 依赖，直接单测）：

```
src/pure/status.ts         # 四态枚举、合法流转校验
src/pure/rating.ts         # 评分范围校验、星级渲染数据
src/data/types.ts          # 类型定义（含默认值工厂 createEmptyEntry）
src/data/catalog.ts        # catalog.json 解析/序列化/迁移/缺字段兜底
src/data/noteGenerator.ts  # frontmatter 生成、详情笔记模板渲染
src/services/tmdb.ts       # TMDB 请求构造 + 响应解析（网络层注入，可 mock）
```

依赖 obsidian 的部分（main.ts/Settings/Views/Modals）保持薄壳，逻辑下沉到上面模块。

## 3. TMDB 接入（探测结论：可行）

| 项 | 实测/文档结论 |
|---|---|
| API Key | 必须注册（免费），需同意服务条款 |
| 搜索接口 | `/3/search/movie`、`/3/search/tv`，query 参数 |
| 中文支持 | `language=zh-CN` 参数（文档确认支持语言配置） |
| 图片 CDN | `image.tmdb.org`，configuration 接口拿 base_url + 尺寸 |
| 速率限制 | 有 rate limiting，需做失败重试与节流 |

实现策略：Key 存设置页；无 Key 时搜索按钮禁用并引导；请求失败友好降级。

## 4. 豆瓣兜底（待验证 — 真实探测）

**探测过程（2026-08-25）**：

| 方式 | 结果 |
|---|---|
| WebFetch（服务端抓取）`search.douban.com/movie/subject_search?search_text=流浪地球` | HTTP 200，**拿到完整结构化数据**（标题/年份/评分/导演/演员/时长/subject ID）→ 数据源服务端可渲染 |
| curl 直接请求（浏览器 UA + X-Requested-With） | HTTP 200 但 **SIZE=0 空响应** → 反爬对请求指纹/IP 敏感 |

**结论**：技术上「偶尔可行、极不稳定」。无官方 API、依赖 HTML 结构解析（接口变动即失效）、爬取行为有合规灰色地带。

**降级预案（建议采纳）**：
1. **默认关闭**豆瓣兜底开关（设置页），v0.0.1 以 TMDB + 手动为主
2. 豆瓣抓取做成独立可插拔源接口（`MetadataSource` 抽象），后续验证可行再开启
3. 预留「自定义 JSON 源」可能性（用户自备数据），但 v0.0.1 不做

## 5. 存储方案评估

| 项 | 评估 |
|---|---|
| catalog.json 全量读写 | MVP 百级条目可接受；写入用原子替换（写临时文件再 rename） |
| 数据一致性 | catalog 为事实源，frontmatter 冗余；reindex 命令可修复漂移 |
| 迁移 | schema version + 迁移函数表（只增不改） |
| 并发 | Obsidian 单实例，插件内串行写；Vault API 的 modify 保证原子性 |

## 6. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 豆瓣爬虫 | 高 | 默认关闭 + 可插拔源 + 合规声明 |
| TMDB 速率限制/网络失败 | 中 | 重试退避 + 手动降级不阻塞 |
| Svelte 4 与 Obsidian 新版兼容 | 中 | 沿用已验证构建链；升级前查 changelog |
| 中文文件名/路径 | 低 | 沿用 lyricflux Unicode 同步方案 |
| 封面图片体积 | 低 | 缩放存储 + 懒加载 |

## 7. 结论

开发视角**可行**：技术栈全复用、纯逻辑可测、存储方案清晰。唯一高风险项豆瓣兜底已通过真实探测定性为「不稳定」，建议 v0.0.1 默认关闭（待用户 G2 确认此降级预案）。
